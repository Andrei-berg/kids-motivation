## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| kid browser → `'use server'` action | Untrusted `childId` + `style` arguments cross here from a client component |
| server action → Postgres (`children`) | Service-role client bypasses RLS entirely — the guard chain is the only authorization |
| developer machine → prod Postgres | Task 2 runs DDL against the live database with `SUPABASE_DB_URL` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-093-01 | Elevation of Privilege | `updateChildFillStyle` (`app/kid/actions/fill-style.ts`) | mitigate | `authorizeChildAction(admin, member, childId)` after `requireFamilyMember()` — a `role === 'child'` member whose `member.childId !== childId` gets `AuthError('Forbidden', 403)`; `assertChildInFamily` then blocks cross-family targets. Byte-identical guard order to `app/kid/actions/avatar.ts`. |
| T-093-02 | Tampering | `children.fill_style` write path | mitigate | No client-side `.update()` on `children` anywhere (asserted by the `grep -c "from('children')" components/kid/ProfileSheet.tsx` = 0 criterion); migration adds no client UPDATE policy, so RLS denies any direct browser write. |
| T-093-03 | Tampering | `style` argument | mitigate | `FILL_STYLES` allow-list check + the D-01 `style !== 'sticky-summary'` reject guard in the action, backed independently by the DB `children_fill_style_check` CHECK constraint — an unbuilt style cannot be persisted even if the action is called directly. |
| T-093-04 | Denial of Service | prod DDL in task 2 | accept | Migration is additive + idempotent (`ADD COLUMN IF NOT EXISTS`, `DO $$` guarded constraint) with a `NOT NULL DEFAULT`; no table rewrite of user data, no destructive statement. | T-093-05 | Information Disclosure | `api.getChild` selecting `*` | accept | `fill_style` is a non-sensitive UI preference; `children` reads are already family-isolated by `rls.sql`, and this adds no new column to any cross-family read path. |
| T-093-SC | Tampering | npm/pip/cargo installs | accept | No new project dependency is added by this phase. Task 2's `npm i pg --no-save` installs the pre-existing, already-in-use Postgres driver named in CLAUDE.md, non-persistently (`--no-save`, never written to `package.json`) — no supply-chain surface change, so the Package Legitimacy Gate has nothing to audit. |
</threat_model>

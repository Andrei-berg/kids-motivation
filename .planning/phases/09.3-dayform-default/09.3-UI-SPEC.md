| 3xl | 64px | not used this phase |

### Spacing-scale exceptions

None — every declared token value above is a strict multiple of 4.

### Component intrinsic sizing (pre-existing, not part of the spacing token scale)

These are locked reuse of existing components per CONTEXT.md D-13, not new spacing decisions for
this phase — they are listed here for completeness but do not count against the 4px spacing scale:

- Sticky summary bar total height is capped at **~70px** (explicit constraint from
  `day-fill-interaction.md`: "don't let the sticky summary bar (C) cover more than ~70px") — the
  ring (56px) + tight vertical padding (7px top/bottom) is the budget.
- `.switch` toggle: 44×26px track, 20×20px thumb, 3px inset — matches existing 44px minimum
  touch-target convention from Phase 4.2 (ux-polish) even though the visible track is narrower;
  the tappable row (`.quick-row`, min-height ~52px per padding: 12px top/bottom around 28px
  content) is the actual hit target, not the switch alone.
- Mood row buttons: `minHeight: 64` (existing `KidDayFillForm.tsx` mood button style) — kept
  unchanged, not a new value.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (row label) | 16px | 700 (`K.fDisp`) | 1.3 |
| Label (muted sub-text, coin tag, hint, ring pct) | 13px | 700 (`K.fBody`/`K.fNum`) | 1.3 |
| Heading (screen title) | 22px | 900 (`K.fDisp`) | 1.2 |
| Display (coin total) | 20px | 900 (`K.fDisp`) | 1.2 |

Exactly 4 sizes (13, 16, 20, 22px) and 2 weights (700, 900) — within the design-contract caps.

Notes:
- Consolidated to these 4 sizes and 2 weights to satisfy the design-contract caps. The sketch's
  original `--text-*` scale (14.5px body, 12–13px label, 20px display, 22px heading, with an
  800-weight label step) was the starting reference but is not used verbatim — every value below
  maps onto real `K` font-stack sizes already shipping on this screen; do not invent a new scale
  or reintroduce the sketch's 14.5px/800-weight values.
- Row labels use `K.fDisp` (Rubik) at weight 700, 16px — matches the existing `.quick-row .lbl`
  pattern and the current `CollapsibleRow` title style (`fontSize: 16, fontWeight: 700`) already
  shipping on this screen; this phase extends real components, not the sketch verbatim (D-13
  "reuse existing state/logic"), and visual continuity with the untouched mood row/other existing
  UI takes precedence over the sketch's 14.5px reference.
- Muted sub-text, coin-delta tags, hints, and the completion ring's percentage label all share the
  single 13px/700 "Label" size — merged into one value (the sketch had these split across
  12–13px at weight 700–800) to stay within the 4-size/2-weight caps. Coin-delta tags
  (`.coin-tag` equivalent) use `K.fNum` (Rubik on the number face) at this 13px/700 size, colored
  `K.mangoDeep` for positive / `K.danger` for negative — mirrors the existing `trailingFor()`
  helper in `KidDayFillForm.tsx` (already implements this exact color-by-sign rule; reuse, don't
  reinvent).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `K.cream` (#FFFDF7) | Page background |
| Secondary (30%) | `K.card` (#FFFFFF) | Row/panel/summary-bar surfaces, `K.lineSoft` (#F2F4F9) for ring track background |
| Accent (10%) | `K.mint` (#12B886) | Reserved for: completion-ring fill arc, `.quick-row.done` border, `.switch` "on" state background, positive coin-delta glow — i.e. anything signaling "done/earned" |
| Destructive/negative | `K.danger` (#D84C5E) | Reserved for: negative coin-delta floating feedback ("-N"), negative coin-delta tag text, negative running-total tick color momentarily (per D-11) |

**Primary visual anchor:** the sticky summary bar (completion ring + live coin total) is the
screen's primary visual anchor — it persists on screen at all times while filling, and it is the
only element that combines the reserved accent color (`K.mint` ring fill) with the largest
display-size typography (20px coin total) on the page, by design drawing the eye first and
staying the constant reference point as rows are filled.

Additional semantic accents already established and reused unchanged this phase (not new
introductions, just confirming their reserved use per D-11/D-08):
- `K.mango` / `K.mangoDeep` (#FF9F2E / #E07E00) — reserved for: the live coin total display only
  (both the sticky-bar total and the existing "coins today" strip), matching the existing
  `mangoSoft`/`mango` "coins today" banner already in `KidDayFillForm.tsx`.
- `K.sky` (#2F7FE4) — reserved for: primary CTA (save button, unchanged), open/focused row
  border state, selected mood emoji's highlight (unchanged from current mood-picker style).
- `K.berry` (#FF6B8A) — available but not mandated for the mood "wow" animation (D-08 discretion);
  if used, reserve strictly for that one-off pop/glow, not as a new recurring UI color.

Accent reserved for: completion-ring arc fill, done-row border/switch state, positive coin-delta
color — never used decoratively elsewhere on this screen.

## Interaction Contract (sticky-summary style, D-01 through D-13)

This section supplements the standard template — it is the phase-specific behavioral contract
the checker/executor need, since DAYFORM-04/05 are fundamentally interaction requirements, not
just visual ones.

### Layout structure (top to bottom)
1. **Sticky summary bar** (persists on screen at all times while filling — `position: sticky` or
   `fixed`, capped ~70px tall): `ProgressRing` (56px, from `components/kid/design/atoms.tsx`,
   reuse verbatim — do not rebuild the conic-gradient by hand) showing completion % (D-09
   denominator rule below) + `AnimatedNum`-driven live coin total (reuse verbatim) + caption
   `kidFillForm.stickyEarnedToday`.
2. **Row list** (`display: flex; flex-direction: column; gap: 8px`), one row per applicable
   category, in this fixed order (matches existing `KidDayFillForm.tsx` render order): behavior →
   room → activities (one row **per** extra activity, per D-05 — not one aggregate row) →
   custom day-blocks (one row **per** block, per D-05) → grades → exercises → sport/sections →
   reading → mood (always last, always-expanded per D-08).
3. **Save bar** — unchanged from today's pinned sticky CTA (`position: sticky; bottom: 76px`),
   `kidFillForm.saveBtn`.

### Row interaction types (three, per D-05/D-06/D-07/D-08)

**A. One-tap binary rows** (room, each activity, each custom block — D-05):
- Visual: `.quick-row` pattern — icon chip + label + trailing `.switch` toggle, entire row is the
  tap target (not just the switch).
- Tap → flips state instantly (no confirm), fires floating coin feedback (gain or D-11 loss
  variant) at that row's position, updates ring numerator/denominator and running total.
- Re-tap when already done → toggles back off (D-10), fires the inverse (negative) floating
  feedback and decrements the ring/total — a real on/off switch, freely reversible pre-save.
- Done-state visual: row border → `K.mint`, `.switch` → `K.mint` filled + thumb slid right, icon
  chip background → `K.mintSoft`.

**B. Inline-panel rows** (grades, sport/coach-rating per section, reading, behavior — D-06/D-07):
- Visual: `.quick-row-wrap` pattern — same-looking row at rest (icon + label + coin-tag trailing,
  not a switch), tap expands a `.mini-panel` **in place** below the row (no bottom sheet, no
  page navigation) using `max-height` transition (`display:none → block` minimum; a smooth
  height transition is preferred but not blocking).
- Only one inline panel open at a time is NOT required by D-07 (unlike the old
  single-open-accordion `openId` state) — re-verify against D-07's literal wording ("expand a
  small inline panel in place, one at a time") — **treat "one at a time" as scoped per multi-value
  category tap**, i.e. tapping a second inline row's header may keep the first one's panel state
  as the implementer judges cleanest, but do not silently auto-close a panel with unsaved partial
  state. (Left as an implementation nuance — the binding requirement is "in place," not modal.)
- Behavior row specifically (D-06): tap target is the row header (not a switch); expands the same
  multi-select tag panel pattern (existing `behaviorBody` in `KidDayFillForm.tsx`, reuse
  unchanged) that proposes tags via `proposeMark`; row shows done/pending visual once ≥1 tag
  proposed for today (reuse existing `done.behavior` logic: `selectedTagIds.length > 0 ||
  behaviorMarks.some(m => m.status === 'pending')`).
- Coin-tag trailing element uses the existing `trailingFor()` color rule (mango/mint-deep for
  positive, `K.danger` for negative) — reuse, don't reinvent.

**C. Always-expanded row** (mood only — D-08):
- No tap-to-open step; the 5-button mood picker (existing `MOOD_OPTIONS_STATIC` render, unchanged
  markup/copy) renders directly under its row header at all times.
- Selecting an emoji triggers a **more pronounced** "wow" animation than the other rows' plain
  state-change (implementer's call on exact curve/scale per D-08 Claude's Discretion) — must be
  gated behind the existing reduced-motion guard pattern (Phase 05.3-02: keyframe inside
  `@media (prefers-reduced-motion: no-preference)` + a post-mount JS fallback check, same pattern
  used for the Stamp animation). No coin delta fires for mood (mood carries no coin value).

### Completion ring denominator/numerator (D-09)
- Include in denominator: any category with something to do today. Mood always counts (always
  applicable). Grades/room/reading/exercise/sport count only when their block is visible per the
  existing `dayBlocksEnabled`/`visibleBlocks` gating (flag-on) or the legacy always-shown gating
  (flag-off) already implemented in `KidDayFillForm.tsx`'s `renderBuiltinBlock`/legacy JSX branch.
- Exclude entirely (not counted as incomplete): a category with nothing configured for this child
  (no sport sections assigned, no behavior tags configured by parent, zero extra activities
  defined) — do not show a 0/1 "stuck incomplete" slice for these.
- Numerator increments per completed category exactly once (a category with multiple sub-items,
  e.g. 2 grade subjects, still counts as ONE numerator slot when done, matching the sketch's
  `doneC++` per category, not per sub-item) — mirrors existing `done.*` boolean map already
  computed in `KidDayFillForm.tsx` (lines ~1136+); reuse that object as the ring's source
  categories, filtered by D-09's applicability rule.

### Live coin feedback (D-11, D-12)
- Fires at the **row's own interaction handler**, immediately on every state-changing tap — not
  batched, not only at final save. Delta source is the existing `sectionCoins` per-category
  breakdown (`KidDayFillForm.tsx` `useMemo`, already computed) — no new coin-calculation logic.
- **Gain** (existing `useCoinAnimation`/`CoinFlyup` mechanism, reuse as-is): floating "+N 🪙"
  rising and fading, `K.mint`-colored, matches existing `floatUp`-style keyframe (opacity 0→1 at
  20%, translateY(-26px) over ~0.8s).
- **Loss** (new variant required by D-11 — does not exist in `CoinAnimation.tsx` today): floating
  "-N 🪙", `K.danger`-colored, **downward drift** (translateY(+26px) or similar — inverse of the
  gain animation, not just a recolor) over a similar ~0.8s duration. Implementer's exact easing
  curve is discretionary (per CONTEXT.md Claude's Discretion) but must read as visually distinct
  in valence, not just in color.
- Running total (`AnimatedNum`, reuse as-is) must genuinely animate downward on a loss (the
  existing cubic ease-out count-up logic in `AnimatedNum` already handles `from > to` correctly —
  confirm during implementation, no rewrite expected).
- Per-row trigger points needed: room toggle, each activity toggle, each custom-block toggle,
  each grade-subject pick, each coach-rating pick, reading toggle, behavior tag propose (if it
  carries a coin value — confirm against real behavior-tag coin rules; today's behavior data model
  has no direct coin value at propose time, only at parent-approval, per Phase 5.9 — if so, the
  behavior row should NOT fire coin feedback at propose time, only reflect done/pending status;
  flag this nuance for the planner to resolve against the real `behavior_marks` coin timing).

### fill_style control (D-01, D-03, D-04)
- Location: `components/kid/ProfileSheet.tsx`, self-serve, alongside the existing avatar-edit
  entry point (same sheet, not a new route/tab).
- Phase 9.3 scope: **only `sticky-summary` is real/selectable** — no 3-way picker yet, no
  "coming soon" placeholders for `tile-sheet`/`story-stepper`. Minimal UI per Claude's
  Discretion: a small confirmed-state pill or note (e.g. "Стиль заполнения: Сводка") is
  sufficient; a fully absent control is also acceptable as long as no dead-end UI for the other
  two styles appears before Phase 9.4.
- Write path: exact mirror of `app/kid/actions/avatar.ts` — a `'use server'` action using
  `requireFamilyMember()` + `authorizeChildAction(admin, member, childId)` +
  `createAdminClient()`, updating `children.fill_style`. Never a direct client
  `.update()` on `children` (RLS blocks it; the avatar action's own comment documents this).
- Schema: `children.fill_style TEXT NOT NULL DEFAULT 'sticky-summary'` + idempotent `DO $$ ...
  CHECK (fill_style IN ('tile-sheet','story-stepper','sticky-summary')) $$` — mirrors the
  `backfill_mode` migration shape exactly (`supabase/migrations/2026-09-10-backfill-day-requests.sql`).

# Phase 09.4 Plan 04: fill_style Guard Removal + ProfileSheet Picker Summary

**Removed the Phase-9.3 scope guard that rejected every fill style but sticky-summary, hardened the remaining runtime whitelist to also reject non-string values as the first statement before any auth/service-role work (locked in by a 5-assertion regression test), and replaced ProfileSheet's single confirmation button with a real 3-option radiogroup that lets a child actually pick tile-sheet or story-stepper — the last piece needed for DAYFORM-01's "all three styles selectable" to be literally true.**

## Accomplishments
- Deleted the five-line "D-01 (Phase 9.3 scope)" comment and the `if (style !== 'sticky-summary') throw ...` guard from `updateChildFillStyle`, replacing the comment with a one-line note naming which plan shipped each style
- Hardened the whitelist check to `typeof style !== 'string' || !(FILL_STYLES as readonly string[]).includes(style)`, kept as the first statement in the function — before `requireFamilyMember()` and `createAdminClient()` — so a malformed value never reaches an authenticated service-role code path (T-094-13)
- Added `tests/fill-style-validation.test.ts`: mocks `@/lib/supabase/admin` (via `vi.hoisted()` + a local `AuthError` class defined inside the mock factory) and `@/app/api/wallet/_lib`'s `authorizeChildAction`; 5 assertions cover a bad-style rejection, that `requireFamilyMember`/`createAdminClient` were never called on that rejection, and that all three real styles (`tile-sheet`, `story-stepper`, `sticky-summary`) get past validation
- Replaced ProfileSheet's single `sticky-summary`-only confirmation button with a `role="radiogroup"` row of three `role="radio"` buttons (order: sticky-summary, tile-sheet, story-stepper), each with `aria-checked`, the existing `K.skySoft`/`K.sky` active styling, the `✓` checkmark convention, and `minHeight: 44` touch targets preserved
- `handleFillStyleTap` now takes the target value instead of a hardcoded string; a new `fillStyleError` state (cleared at the start of every attempt) surfaces a rejected write as a visible inline error line in addition to the existing `console.warn`
- Retired `kidProfile.fillStyleActive` from both `ru.json` and `en.json` — confirmed by grep that no source file references it any more

## Decisions Made
- Used `vi.hoisted()` to share `mockRequireFamilyMember`/`mockCreateAdminClient`/`mockAuthorizeChildAction` between the `vi.mock()` factory bodies and the test bodies, and defined the local `AuthError` class *inside* the `@/lib/supabase/admin` mock factory (not as a top-level const) — a top-level class reference inside a hoisted `vi.mock()` factory throws "Cannot access before initialization" because the factory runs before the module's own top-level statements execute
- `fillStyleError` is intentionally a separate boolean from `savingFillStyle` (not reused/overloaded) so the saving-in-progress and error states are independently readable in the JSX

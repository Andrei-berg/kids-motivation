# Phase 9.4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**No RESEARCH.md exists for this phase** (same as 9.3 — `/gsd:plan-phase` may judge CONTEXT.md
detailed enough to skip a separate technical-research pass). Every stack/pattern decision below
comes from the existing codebase, already cited file-by-file in `09.4-CONTEXT.md`'s
`<canonical_refs>`, plus the validated sketch HTML
(`.claude/skills/sketch-findings-kids-motivation/sources/002-day-fill-form/index.html`,
`#variant-a` tile+sheet, `#variant-b` story-stepper — `#variant-c` was already built in Phase 9.3
as `sticky-summary`).

**Continuity requirement:** this phase adds two new render shells around the exact same
`KidDayFillForm.tsx` state/logic Phase 9.3 already built (D-13 reuse principle) and must stay
visually consistent with Phase 9.3's shipped `sticky-summary` style — same palette, same type
scale, same coin-flyup mechanism. This UI-SPEC intentionally reuses 9.3's Design
System/Spacing/Typography/Color sections verbatim where nothing phase-specific changes, and adds
new sections only for what's actually new (tile grid, bottom sheet, dot-track stepper).

| Property | Value |
|----------|-------|

for kid-screen color/type. Do NOT introduce new hex values or a second token object; every color
below is an existing `K.*` key or an established `${K.hex}alpha` soft-tint idiom already used in
this codebase (e.g. the `saveError` banner's `${K.danger}14` background / `${K.danger}40` border).

## Spacing Scale

Declared values (must be multiples of 4) — identical to Phase 9.3's declared scale, reused
unchanged:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, dot-track gap |
| sm | 8px | Tile grid gap, row-list gaps |
| md | 16px | Screen-edge padding, tile padding, sheet horizontal padding |
| lg | 24px | Section spacing, step-card vertical margin |
| xl | 32px | not used this phase |
| 2xl | 48px | not used this phase |
| 3xl | 64px | not used this phase |

### Spacing-scale exceptions

None — every declared token above is a strict multiple of 4. Where the sketch's raw CSS used a
non-multiple value, round to the nearest declared token rather than copying verbatim (e.g. the
sketch's `.tile-grid { gap: 10px }` → use `sm` (8px); the sketch's `.tile { padding: 14px }` →
use `md` (16px)) — matches Phase 9.3's precedent of not porting sketch pixel values 1:1.

### Component intrinsic sizing (pre-existing/sketch-validated, not new spacing tokens)

Listed for completeness, not counted against the 4px spacing scale — these are either reused
from Phase 9.3 or taken directly from the validated sketch CSS as fixed component dimensions:

- **Tile grid:** `grid-template-columns: 1fr 1fr` (strict 2-column, no responsive reflow — per
  DAYFORM-02's explicit "2-column grid" wording and CONTEXT.md's confirmation this is not an
  open question).
- **Bottom sheet:** `border-radius: 22px 22px 0 0` (sketch value, kept as-is — close enough to
  the existing 18px kid card radius that a new token isn't warranted for this one-off shape);
  grip handle `40×4px`; slide transition `transform .28s cubic-bezier(.2,.9,.3,1.1)` (sketch's
  exact easing, per CONTEXT.md's Claude's Discretion note to use it as the base).
- **Dot-track:** dot height `5px`, gap `6px` (rounds to `xs`), fill transition `width .3s`
  (sketch values, kept as-is — a 5px dot doesn't map cleanly onto the 4px scale and isn't worth
  forcing to 4px/8px at this visual weight).
- **Step card:** `min-height: 340px`, `border-radius: 24px` (sketch values; note this is *larger*
  than the standard 18px kid card radius — intentional, the step-card is a full-screen hero
  moment, not a list-row card).
- **Grade/choice buttons inside sheets and steps:** `52×52px` (grade), same as Phase 9.3's
  existing `grade-btn` sizing already shipping in the reused body JSX — unchanged.
- **Persistent stepper coin header (D-09):** target height budget ~44-48px (single row, no ring)
  — deliberately smaller than sticky-summary's ~70px budget since the dot-track needs its own
  ~30px band directly below it; combined header+dots band should stay under ~90px total so the
  step-card itself remains the dominant visual element on screen.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (row/tile label) | 16px | 700 (`K.fDisp`) | 1.3 |
| Label (muted subtext, coin tag, hint, dot/ring pct) | 13px | 700 (`K.fBody`/`K.fNum`) | 1.3 |
| Heading (screen title, sheet title) | 22px | 900 (`K.fDisp`) | 1.2 |
| Display (coin total, step-card title) | 20px | 900 (`K.fDisp`) | 1.2 |

Same 4 sizes (13/16/20/22px) and 2 weights (700/900) as Phase 9.3 — reused unchanged, not
re-declared, so all three fill styles read as one consistent screen family. Notes specific to
this phase's new surfaces:

- **Tile title** (`.tile .t`, e.g. "Комната") → Body (16/700), same as a sticky-summary row
  label. **Tile status subtext** (`.tile .s`, e.g. "Не заполнено" / "2 предмета") → Label
  (13/700), colored `K.ink3` at rest / `K.mintDeep` when done / `K.danger` when net-negative
  today (D-17).
- **Sheet title** (`.sheet h3`, e.g. "🧹 Комната") → Heading (22/900) — the sketch's 17px/800 is
  consolidated up into the existing Heading bucket rather than adding a 5th size.
- **Step-card title** (`.step-card h2`, e.g. "Комната") → Display (20/900) — matches the
  sketch's own 20px/900 value exactly, no rounding needed.
- **Step-card description** (`.step-card p`, e.g. "Убрал(а) сегодня комнату?") → Label
  (13/700) — the sketch's 13.5px rounds down into the existing Label bucket.
- **Step-card icon** (`.step-card .ic`, 52px emoji) is a glyph, not typography — not part of this
  scale, same treatment as the mood-picker's 24px emoji in Phase 9.3.
- **Stepper persistent coin header (D-09)** reuses the Display (20/900) size for the number
  (matching sticky-summary's coin total) and Label (13/700) for its caption — no new size.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `K.cream` (#FFFDF7) | Page background |
| Secondary (30%) | `K.card` (#FFFFFF) | Tile/sheet/step-card surfaces, `K.lineSoft` (#F2F4F9) for dot-track/ring track background |
| Accent (10%) | `K.mint` (#12B886) | Reserved for: `.tile.done` border + soft fill, sheet "done" toggle state, dot-track `.fill` (completed step), tile checkmark badge |
| Destructive/negative | `K.danger` (#D84C5E) | Reserved for: tile loss tint (D-17 — net-negative-today categories, e.g. a low grade), negative coin-flyup (already built in `app/globals.css` `.coin-flyup-number.loss` / `@keyframes coin-flyup-loss` from Phase 9.3 — reuse verbatim, no new CSS) |

Additional semantic accents reused unchanged from Phase 9.3 (not new introductions):
- `K.sky` (#2F7FE4) — reserved for: primary CTA (Save button in both styles, unchanged), the
  **current** dot in story-stepper's dot-track (`.dot.current .fill` uses sky, not mint — matches
  the sketch exactly: mint = done, sky = currently-on this step), sheet-open focus border.
- `K.mango`/`K.mangoDeep` (#FF9F2E/#E07E00) — reserved for: the live coin total only, in both
  the tile-sheet's reused `StickySummaryBar` (D-08) and the story-stepper's new persistent coin
  header (D-09).
- `K.berry` (#FF6B8A) — available for the mood step's "wow" pop animation glow (D-05, reusing
  Phase 9.3's `kidMoodPop` keyframe verbatim), not a new recurring UI color.

**Tile loss tint (D-17, new this phase):** use the established `${K.danger}alpha` soft-surface
idiom already shipping in `KidDayFillForm.tsx`'s error banner (`background: ${K.danger}14`,
`border: 1.5px solid ${K.danger}40`) rather than inventing a `dangerSoft` token — apply this same
pair to `.tile` when that category's `sectionCoins` value for today is negative, with the status
subtext colored solid `K.danger`. This is a **third** tile state alongside `done` (mint) and
at-rest (neutral `K.line`/`K.lineSoft`) — never combine mint-done styling with a negative value in
the same tile.

Accent reserved for: done-state fill (tile border/badge, dot fill, sheet toggle), current-step
indicator (dot only) — never used decoratively elsewhere on these two screens.

## Interaction Contract — Tile-Sheet style (D-01, D-02, D-03, D-08, D-14, D-16, D-17, D-18)

This section supplements the standard template — DAYFORM-02 is fundamentally an interaction
requirement, not just a visual one.

### Layout structure (top to bottom)
1. **`StickySummaryBar`** (D-08) — the exact same component Phase 9.3 built
   (`components/kid/day-fill/StickySummaryBar.tsx`), reused verbatim, same ~70px height budget.
   Import and render as-is; do not fork a tile-sheet-specific header.
2. **Tile grid** — `display: grid; grid-template-columns: 1fr 1fr; gap: 8px` (sm token),
   `padding: 16px` (md token). One tile per applicable category **and per individual real-data
   item** (D-01): room, behavior, grades, exercises, sport/sections, reading — one tile each
   (D-03) — plus **one tile per extra activity** and **one tile per custom day-block** (not one
   aggregate "Activities" tile), plus **one tile for mood** (D-02). A family with several
   activities/custom blocks configured can legitimately produce an 8-12+ tile grid — this is
   expected, not a bug to "fix" by grouping.
3. **Bottom sheet** (portal/fixed overlay, not part of grid flow) — opens on tile tap, scoped to
   exactly one category's existing body JSX (`roomBody`, `extraActivitiesBody`, `gradesBody`,
   `exercisesBody`, `sectionsBody`, `readingBody`, or the mood picker markup) reused unchanged.
4. **Save bar** — unchanged from sticky-summary's pinned CTA (D-14): same component/position,
   same "save partial, reopen later" behavior, no new completion gate.

### Tile visual states (three, per D-17)
- **At rest:** `border: 1.5px solid K.line`, `background: K.card`, status subtext `K.ink3`
  (`kidFillForm.tileNotFilled` or category-specific status like grade count).
- **Done / positive:** `border-color: K.mint`, `background: K.mintSoft`, status subtext
  `K.mintDeep`, small checkmark badge (top-right, `K.mint` fill, white check) visible.
- **Done / net-negative today (D-17, new):** `background: ${K.danger}14`,
  `border: 1.5px solid ${K.danger}40`, status subtext solid `K.danger` — mutually exclusive with
  the mint done-state; a tile is never both mint and danger-tinted at once. Determine via the
  existing `sectionCoins`/`diffSectionCoins` per-category value (`lib/kid/day-fill-progress.ts`,
  reused unchanged) being negative for that category today.
- Tap feedback: `transform: scale(0.97)` on `:active` (sketch value, kept as-is — a cheap
  perceptible press without a new keyframe).

### Bottom sheet behavior (D-16, D-18)
- Opens via the `.kid-bottom-sheet`/`kid-slide-up` pattern already in `app/globals.css` (lines
  ~4375-4383: `transform: translateY(100%) → translateY(0)`, `.3s ease-out`) **or** the sketch's
  own slightly different easing (`.28s cubic-bezier(.2,.9,.3,1.1)`, per CONTEXT.md's Claude's
  Discretion to use the sketch CSS as the base) — implementer's call which exact curve, but must
  land on one canonical bottom-sheet animation, not a third bespoke one.
- **Reduced-motion gap to close:** the existing `.kid-bottom-sheet`/`kid-slide-up` class is
  **not yet double-guarded** for `prefers-reduced-motion` (no `@media` wrapper, unlike the
  established Phase 05.3-02 idiom `CoinAnimation.tsx`/mood-pop already follow). This phase must
  add that guard (keyframe inside `@media (prefers-reduced-motion: no-preference)` + a static
  fallback) when building/reusing the sheet animation — do not ship an unguarded new animation.
- Scrim/backdrop present (sketch's `.sheet-backdrop`, `rgba(20,20,30,0.45)`), tapping it closes
  the sheet — same effect as the explicit close control.
- **Explicit close required, every category, no exceptions (D-18):** an X button and/or the
  scrim-tap/swipe-down gesture — but never an auto-close triggered by a single answer tap (e.g.
  picking a mood emoji inside its sheet must NOT immediately dismiss it). Use the existing
  `kidFillForm.sheetDone`/similar explicit "Готово" button already validated by the sketch
  (`sheetToggle`/`sheetGrades`/`sheetMood`'s "Готово" button) as one acceptable close affordance,
  alongside the X/backdrop.
- **Coin flyup anchor (D-16):** reuse the exact `data-fill-row` + `onPointerDownCapture` +
  `useCoinAnimation`/`CoinFlyup` mechanism from `KidDayFillForm.tsx` unchanged — tag the
  interactive elements **inside** each sheet body with `data-fill-row` so the flyup anchors at
  the tap point inside the sheet, not at a fixed position near the header. No new anchoring
  logic, only new markers on already-reused body JSX.
- Closing the sheet updates the originating tile in place with **no page reflow** (DAYFORM-02's
  binding requirement) — the grid itself never remounts or re-sorts on sheet close.

### Locked day (D-13)
- Grid still renders normally (tiles show their filled/unfilled/loss state as saved). Tapping a
  tile still opens its sheet, but the sheet renders **read-only**: no toggle/edit controls, no
  "Готово" save-and-close action beyond a plain close (X/backdrop/swipe only). `StickySummaryBar`
  already supports this via its existing `lockedLabel` prop — pass it through unchanged.

## Interaction Contract — Story-Stepper style (D-04, D-05, D-09, D-10, D-11, D-12, D-15, D-16, D-18)

### Layout structure (top to bottom)
1. **Persistent coin header** (D-09, new component this phase) — slim single row, coin total
   (`AnimatedNum`, reused from `atoms.tsx`) + caption, target height ~44-48px, no ring (the
   dot-track below already conveys completion %). Exact stacking order relative to the dot-track
   (above it vs. combined into one row) is implementer's call per CONTEXT.md's discretion note —
   both must stay visible together throughout the flow.
2. **Dot-track** (`.dot-track`, `display: flex; gap: 6px; padding: 14px 16px 4px`) — one dot per
   **applicable** category only (D-10's applicable-map, reused from 9.3's D-09 logic — a category
   with nothing configured for this child is excluded from the sequence, not shown as an empty
   step). Category grouping is **coarser** than tile-sheet (D-04): all extra activities collapse
   into one "Activities" step (checklist of all of them together), all custom day-blocks collapse
   into one "Custom" step — room/grades/sport/reading/behavior/mood each still get their own step
   (same boundaries as D-03/tile-sheet). Dots are tappable (D-12) — tapping any earlier dot jumps
   back to that step, Instagram-Stories-style, to change an answer.
3. **Step card** (`.step-card`, `min-height: 340px`, `border-radius: 24px`, centered
   icon+title+description+control) — full-screen-width, one category's reused body content
   presented as the step's control (checklist for Activities/Custom steps, existing grade/toggle/
   mood-picker markup for single-item steps).
4. **Nav row** — explicit skip control only (D-11: "Пропустить →", advances without writing
   anything for that category — no back button is required since D-12's tappable dots already
   cover "go back").
5. **Summary screen** (D-15, replaces "step N+1" after the last applicable category) — recap +
   coin total + the same Save button component/behavior as sticky-summary/tile-sheet (D-14
   parity) — implementer's call on exact recap content (list of what was filled vs. just the
   total) per CONTEXT.md's discretion.

### Dot states (three — current / done / not-yet-visited)
- **Not-yet-visited:** `.dot .fill { width: 0%; background: K.line }` (empty track).
- **Done:** `.dot .fill { width: 100%; background: K.mint }`.
- **Current:** `.dot.current .fill { background: K.sky }` — width reflects partial progress only
  if that step has sub-items (e.g. mid-checklist on the Activities step); otherwise treat as 0%
  fill with the sky color signaling "you are here." Sketch's exact visual treatment beyond this
  is implementer's discretion per CONTEXT.md.
- **No fourth "skipped" state** (D-11) — a skipped category's dot stays in its normal
  not-yet-visited state, visually indistinguishable from "haven't gotten there yet."

### Auto-advance behavior (D-10)
- Completing a step's control (toggle on, grade picked, mood picked, checklist item checked for
  single-item categories) auto-advances to the **next applicable, not-yet-done** step — walks the
  full applicable sequence, never silently skips an applicable step that has nothing entered yet.
- A brief confirmation moment before advancing (sketch's toast pattern, `kidFillForm.stepDoneToast`
  "Готово! ✓", ~450ms delay) is the validated reference — implementer may keep or simplify, but
  the advance must not feel instantaneous/jarring (some acknowledgment beat is expected).
- For the two **grouped** steps (Activities, Custom — D-04), auto-advance triggers only once the
  whole checklist for that step is addressed, not after the first item — implementer's call on
  the exact "addressed" definition (e.g. every visible checklist item tapped at least once vs. an
  explicit "next" tap on that step), staying consistent with D-10's "never auto-skip an
  applicable step" principle.

### Coin feedback (D-16, D-09)
- Same `data-fill-row` + `onPointerDownCapture` + `useCoinAnimation`/`CoinFlyup` mechanism as
  tile-sheet — anchors at the tapped control inside the step card. Tag the step's interactive
  elements (grade buttons, toggle, checklist rows) with `data-fill-row`.
- The persistent coin header's `AnimatedNum` ticks on every fill, same as `StickySummaryBar`'s
  total — reuse the count-up logic verbatim, no new animation.
- Loss variant (grade ≤3, negative coach rating, etc.) reuses the existing
  `.coin-flyup-number.loss`/`coin-flyup-loss` keyframe from Phase 9.3 unchanged.

### Mood step (D-05)
- Full-screen step like any other (not a persistent strip) — same 5-option `MOOD_OPTIONS_STATIC`
  markup reused unchanged. Selecting an emoji plays the existing `kidMoodPop` keyframe (reused
  verbatim from Phase 9.3, already reduced-motion-guarded) then auto-advances like any other step
  (D-10) — mood carries no coin value, so no coin-flyup fires for this step.

### Locked day (D-13)
- Dot-track still renders showing the day's actual final state. Tapping a dot opens that step
  **read-only**: no auto-advance/skip UI (nothing can change), the step-card shows the saved
  answer only. No fallback to sticky-summary's locked view — the kid always reviews a locked past
  day in their own chosen style.

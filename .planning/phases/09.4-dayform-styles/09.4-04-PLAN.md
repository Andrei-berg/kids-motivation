<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| kid browser → `updateChildFillStyle` server action | Arguments arrive over the wire from an untrusted client; the TypeScript `FillStyle` type is compile-time only |
| server action → `children` table | Service-role client bypasses RLS; the only authorization is the guard chain inside this action |
| child member → sibling's child row | `authorizeChildAction` is the sole barrier preventing one child from changing another's preference |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-094-13 | Tampering | `updateChildFillStyle(style)` | mitigate | Runtime whitelist against `FILL_STYLES` plus an explicit `typeof style !== 'string'` check, evaluated as the first statement before `requireFamilyMember()` and `createAdminClient()`; `tests/fill-style-validation.test.ts` asserts a bogus value rejects AND that the auth/service-role spies were never called. The column's own CHECK constraint (`children_fill_style_check`) remains the database-level backstop. |
| T-094-14 | Elevation of Privilege | cross-child write | mitigate | `requireFamilyMember()` + `authorizeChildAction(admin, member, childId)` are preserved verbatim; acceptance criteria grep-assert all three chain members still exist. A child member may only target their own linked child; any member's target must be in their family. |
| T-094-15 | Tampering | scope-guard removal | mitigate | The guard is removed only in wave 4, after plans 02 and 03 have shipped both render shells, so no child can select a style that does not exist. The regression test pins the post-9.4 expectation (all three pass validation) so a later accidental reintroduction fails CI. |
| T-094-16 | Information Disclosure | picker error line | accept | The error surface is a generic localized string (`kidProfile.fillStyleError`); the underlying `AuthError` message/status stays in `console.warn`, so no server-side detail is rendered to the child. |
| T-094-17 | Repudiation | fill_style change | accept | A UI preference change is not an audited action type (`parent_audit_events` covers money/consent actions); no audit row is expected or added here, consistent with the avatar-update precedent. |
| T-094-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan. Package Legitimacy Gate not applicable. |
</threat_model>

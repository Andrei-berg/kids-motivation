# Phase 09.1 Plan 03: Story Reel + Recognition Moment Summary

**Instagram-Stories-style per-child "today's biggest highlight" reel above the day-grouped Family Feed, tapping through to a full-bleed celebratory modal — zero new Supabase queries, zero coin amounts.**

## Accomplishments
- `todaysHighlights` memo derives one `{ child, event }` pair per child from `groups[0]` (today's bucket only, guarded on the `dayLabel()` literal `'Сегодня'`), grouping today's already-fetched events by `child_id` and picking the highest-ranked one via `pickHighlight()`. No Supabase query added — `getFeed(` call-site count stays at 2 (initial load + `loadMore`).
- `storySeen` state populated in a `useEffect` keyed on `[familyId, todaysHighlights]`, calling `getStorySeen(familyId, childId, localDateString())` per highlight — localStorage is read only inside the effect, never at render time (`window.localStorage` direct-call count in the component: 0, enforced via `feed.repo` helpers only).
- `StoryReel` renders a horizontally-scrollable row of `StoryBubble`s above the day-grouped list; returns `null` (no heading, no placeholder) when zero children qualify (D-05).
- `StoryBubble`: 62×62 ring — 4-stop `linear-gradient(K.mango, K.berry, K.grape)` when unseen, flat `K.line` border when seen — around a hand-rolled avatar circle (`child.emoji || event.icon || '⭐'`), matching `EventRow`'s existing avatar-circle idiom rather than importing the `Avatar` atom, per the file's established consistency.
- `StoryMomentModal`: full-bleed centered overlay reusing `ProfileSheet`'s dialog/backdrop/stopPropagation shape (`alignItems: 'center'` instead of `'flex-end'`, `zIndex: 260` above `ProfileSheet`'s 240). Gradient background derived from `RAIL_COLOR_MAP[event.kind] ?? K.grape`; shows `event.icon`/`event.title`/`event.body` enlarged (22px/700 Display row); dismiss via Escape keydown listener, backdrop click, or an icon-only 44×44 × button (`aria-label="Закрыть"`). No `event.amount` reference anywhere in the component.
- Wired `StoryBubble`'s tap through `openStoryMoment()`: opens the modal, calls `markStorySeen(familyId, childId, localDateString())`, and optimistically flattens the ring via `setStorySeen` before the next mount (D-07 — seen marked on open, not close).

## Issues Encountered
- `tsc --noEmit` initially failed with `TS2802: Type 'Map<string, FeedEvent[]>' can only be iterated through when using the '--downlevelIteration' flag`. Fixed by wrapping the iteration in `Array.from(byChild.entries())`, matching how `Array.from`/spread is already used elsewhere in this file (e.g. `[...children]` isn't present, but the codebase's TS target requires this pattern for `Map`/`Set` iteration generally). Re-verified `tsc --noEmit` clean.
- Task 2's own acceptance-criteria grep for "no `event.amount` reference" initially matched the explanatory comment I'd written above `StoryMomentModal` (which literally said "`event.amount` must never be referenced here" as a warning to future editors) — ironic self-defeat of the same guard plan 09.1-01's SUMMARY hit for a different string. Reworded to avoid the literal token; re-verified grep count = 0.
- `npm run build` failed in this worktree on missing Supabase env vars while statically collecting `/api/cron/daily`'s page data — confirmed the worktree has no `.env.local` (gitignored files aren't copied into `git worktree add` checkouts) while the main repo does. Copied the file across (untracked, confirmed via `git check-ignore -v .env.local`); build then succeeded (exit 0, all routes compiled).

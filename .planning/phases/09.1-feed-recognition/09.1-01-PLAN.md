Export three symbols:

1. `RANK_ORDER: FeedEventKind[]` in this exact order (highest significance first, per D-04):
   `badge`, `medal`, `boost`, `streak`, `reading_approved`, `reward_approved`, `purchase`,
   `day_filled`. Add a doc-comment recording that `kind === 'boost'` is a single tier — the DB
   and every emitter write `kind: 'boost'` for both weekly_boost and boost_milestone, the two

2. `pickHighlight(events: FeedEvent[]): FeedEvent | null` — returns `null` for an empty array;
   otherwise sorts a **copy** (`[...events]`, never mutate the caller's array — `rankChildren`
   does the same) ascending by rank index, tiebreaking on newest `created_at`, and returns
   element 0. **Critical:** resolve a kind's rank via a helper that maps a kind absent from
   `RANK_ORDER` (`note`, `level_up`, `coins_earned`, `coins_spent`) to `RANK_ORDER.length`, NOT
   to the raw `RANK_ORDER.indexOf(...)` result — a bare `indexOf` returns `-1` for unranked
   kinds, which would sort them ahead of `badge`. The snippet in `09.1-PATTERNS.md` uses the
   bare `indexOf` form and must be corrected here.

3. `RAIL_COLOR_MAP: Partial<Record<FeedEventKind, string>>` with exactly these 10 entries and
   no others (locked by D-08 / UI-SPEC "Rail Color Map"):
   `boost` → `K.mango`, `streak` → `K.mango`, `medal` → `K.berry`, `badge` → `K.berry`,
   `day_filled` → `K.mint`, `reading_approved` → `K.grape`, `level_up` → `K.grape`,
   `purchase` → `K.sky`, `reward_approved` → `K.sky`, `note` → `K.line`.
   Add a comment stating that `coins_earned` / `coins_spent` are deliberately omitted (zero
   emitters exist) and that no penalty/correction kind may ever be added here (FEED-04 / D-03).
   Reference `K.*` tokens, never literal hex strings, in the map itself.

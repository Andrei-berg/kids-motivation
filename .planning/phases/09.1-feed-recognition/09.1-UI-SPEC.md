# Phase 9.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn deliberately not used |
| Preset | not applicable |
| Component library | none (hand-rolled React function components, inline `style` objects — no CSS framework component layer) |
| Icon library | none — emoji glyphs only (`child.emoji`, `family_events.icon`), consistent with the entire kid design system |
| Font | Rubik (`K.fDisp`, headings/numbers) + Nunito (`K.fBody`, body text) via CSS vars `--font-kid-display` / `--font-kid-body` on kid variant; daylight `family/parent` variant keeps its existing `familyBase.fontDisplay`/`fontBody` (Bitter/Golos, unchanged by this phase) |

**Why no shadcn:** `components.json` is absent from the repo and the project has an established,
5-milestone-deep custom design-token system (`lib/design/tokens.ts` for parent "paper"/"ink"
themes, `components/kid/design/kidTheme.ts` for the kid theme) with hand-rolled shared atoms
(`components/kid/design/atoms.tsx`). CLAUDE.md and this phase's orchestrator brief both state the
stack is "Next.js 14 + Tailwind + custom inline-style design tokens... the established pattern
this phase must extend, not replace." Introducing shadcn now would fork the design system
mid-milestone. This phase extends `kidTheme.ts` (`K`) and `atoms.tsx` (`CollapsibleRow`'s rail
pattern) exactly as instructed — no new component library is introduced.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside chips/pills, ring padding (`.story-ring` padding: 3px is an existing sketch-validated exception, see below) |
| sm | 8px | Reaction-row gaps, chip internal spacing |
| md | 16px | Default spacing between cards, story-reel row padding, modal content padding |
| lg | 24px | Section breaks (story reel → day-group label, day-group → day-group) |
| xl | 32px | Modal top/bottom safe-area padding |

Exceptions (carried over unchanged from the existing, already-shipped kid design system — do not
"fix" these to fit 8pt during this phase, but do not introduce any *new* off-scale values either):
- `18px` card border-radius (`CollapsibleRow`, `.synth-card`) — established shape token
- `14px` card body padding (`.synth-body`, existing `EventRow`) — established
- `12px`/`13px`/`10px` internal gaps inside `EventRow`/`CommentThread` — established, pre-existing
- `62px` story bubble diameter, `3px` ring padding, `5px` rail width — locked values from the
  validated sketch CSS (`.story-ring`, `.synth-rail`), reused verbatim

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label (meta/timestamp/day-group header/reaction count) | 12px | 700 | 1.3 |
| Body (card sub-line, comment text, note body) | 14px | 400 | 1.5 |
| Heading (card headline, story-bubble name) | 16px | 700 | 1.35 |
| Display (story-moment modal hero line) | 22px | 700 (800 exception, see below) | 1.15 |

Exactly 2 weights declared: **400 (regular, Nunito body)** and **700 (bold, Rubik headings/labels/numbers)**.

Exception: the single large stat number inside the story-moment modal hero (e.g. a big "🔥 7"
streak count or "🏅" badge glyph) may use **800 (extrabold)**, matching the existing
`CoinPill`/`XPBar`/`SectionHeader`/`StreakFlame` convention already shipped in
`components/kid/design/atoms.tsx` — this is a pre-existing codebase convention for the one
"hero number" moment per screen, not a new arbitrary third weight introduced by this phase. Do
not use 800 anywhere else in this phase's new UI.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Kid variant: `K.cream` `#FFFDF7` · Parent/family variant: daylight `#F6F4EF` (`lib/design/tokens`) | Page background behind the story reel and feed list — unchanged from today, not a decision of this phase |
| Secondary (30%) | `K.card` / `#FFFFFF` (both variants use white cards) | `.synth-card` surface, story-moment modal panel, story bubble background |
| Accent (10%, categorical — see Rail Color Map) | See table below | **Never** decorative — each hex is reserved for exactly one semantic event category, per D-08 |
| Destructive | `K.danger` `#D84C5E` | Not used anywhere in this phase's Feed UI (no destructive action exists here — no delete/remove in scope). Reserved token only, carried for consistency with the rest of the app. |

This phase's "accent" role is **categorical, not singular** — it is the existing `kidTheme.ts`
semantic palette (`K.sky/grape/mint/mango/berry`), where each color means one specific thing and
is never reused for plain decoration. This is the correct application of the 60/30/10 rule for
this design system: the 10% "accent" budget is spent entirely on these category signals (rail,
story ring, chip "lit" state), never on generic buttons/backgrounds.

| `medal` | berry | `K.berry` `#FF6B8A` |

per-category): `conic-gradient(from 180deg, var(--mango), var(--berry), var(--grape), var(--mango))`

border in `K.line` (neutral), never a color from the gradient.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | None new in this phase. The existing composer button ("Опубликовать") is unchanged. The story-moment modal's dismiss control is **icon-only** (× in a top-right 44×44px tap target, or tap-outside-to-dismiss) — no text label needed. |
| Empty state — story reel | Not a message, a **structural omission**: if zero children have any `family_events` today, render nothing where the story reel would be (no heading, no placeholder row, no "no highlights yet" text) — per D-05, absence is the correct empty state, not an empty-state message. |
| Empty state — day-grouped feed | Unchanged existing copy: "Пока пусто. Заполните день или отметьте награду — событие появится здесь." (already correct: no money, encourages action) |
| Error state | Not currently implemented in `FamilyFeed.tsx` (load failures fail silently). Not a requirement of this phase (FEED-01..04 do not mention error handling) — **optional** if the executor touches the fetch path anyway. If added: heading "Не удалось загрузить ленту", body "Проверьте соединение и повторите", action button "Повторить". |
| Destructive confirmation | Not applicable — no destructive action exists in this phase's scope. |

### Content rules (hard constraints — see Requirements FEED-03/FEED-04 and Decisions D-01–D-03)

1. **No coin/money amount ever renders on any card**, for any `kind` — not just `purchase`. Remove
   the existing `{e.amount > 0 ? '+' : ''}{e.amount}🪙` span from `EventRow` entirely for every
   event kind. The `amount` field stays in the data model and keeps being written by
   `emitFeedEvent` call sites (used internally for highlight ranking) — only the render is removed.
2. Purchase/reward-approval titles already read "Покупка: {reward_title}" / "Награда получена:
   {reward_title}" at the data layer (no price embedded in `title`) — no title-string change
   needed, only the amount span removal above.
3. No penalty/correction/negative-behavior-tag card can ever appear — confirmed zero emitters
   exist (D-03). Do not add a rail color, icon treatment, or card style for such a kind; if a
   future phase adds one, it must not target `family_events`.

### Story bubble seen/unseen storage (D-06)

Follow the existing `feed_seen_${familyId}` pattern in `lib/repositories/feed.repo.ts`. New key
shape: `story_seen_${familyId}_${childId}_${YYYY-MM-DD}` (today's local date). Presence of the key
= seen (flat border); absence = unseen (gradient ring). Purely client-side `localStorage`, never
written to the DB — consistent with existing whole-feed seen-tracking.

### Highlight ranking (D-04, starting point — refine during implementation if needed)

Highest wins, per child, per day: `badge` > `medal` > `boost` > `streak` (bonus/record) >
`reading_approved` > `reward_approved` > `purchase` > `day_filled`. Achievement-type events must
outrank the routine `day_filled` event; exact adjacent-pair ordering is implementation discretion.

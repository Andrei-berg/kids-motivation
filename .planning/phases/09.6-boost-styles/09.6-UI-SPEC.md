# Phase 9.6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**No RESEARCH.md exists for this phase** (same precedent as 9.3/9.4/9.5 — `09.6-CONTEXT.md` was
judged detailed enough to skip a separate technical-research pass). Every stack/pattern decision
below comes from the existing codebase (cited file-by-file in `09.6-CONTEXT.md`'s
`<canonical_refs>`), the validated sketch HTML
(`.claude/skills/sketch-findings-kids-motivation/sources/003-weekly-boost/index.html`, `#variant-b`
and `#variant-c` — `#variant-a` was built in Phase 9.5), and `lib/kid/boost-rules.ts` as the real
data source (BOOST-06).

**Continuity requirement:** this phase plugs two new bodies into Phase 9.5's exact `BottomSheet`
container and does not touch `segmented-bar` (D-13). This UI-SPEC reuses Phase 9.3/9.4/9.5's Design
System/Spacing/Typography sections verbatim (same as 9.5 reused 9.3/9.4's) and adds new sections
only for what's actually new: the quest-checklist row list, the ring+tier-badges body, the tier-badge
popover, and the `boost_style` picker's completion into a real 3-way radiogroup.

All design decisions referenced below (D-00..D-16) are from `09.6-CONTEXT.md` — this document does
not re-litigate them, it translates them into an executable visual/interaction contract.

## Spacing Scale

Declared values (must be multiples of 4) — identical to Phase 9.3/9.4/9.5's declared scale, reused
unchanged:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, chip internal gaps, zone gaps |
| sm | 8px | Row group gaps, chip row gap, tier badge row gap, week-dot row gap |
| md | 16px | Sheet horizontal padding, card margins, row horizontal padding |
| lg | 24px | not used this phase |
| xl | 32px | not used this phase |
| 2xl | 48px | not used this phase |
| 3xl | 64px | not used this phase |

### Spacing-scale exceptions

None — every declared token above is a strict multiple of 4. Where the sketch's raw CSS used a
non-multiple value, round to the nearest declared token (Phase 9.4/9.5 precedent): sketch's
`.quest-item { padding: 13px 16px }` → vertical rounds to 12px (component-intrinsic, see below,
not a spacing-scale token — same treatment as 9.5's 10px sub-bar track height), horizontal stays
`md` (16px). Inter-element gaps between repeated sibling elements (tier badges, week-dots) are not
treated as component-intrinsic sizing — they round to the existing `sm` (8px) token, see below.

### Component intrinsic sizing (pre-existing/sketch-validated, not new spacing tokens)

**Quest-checklist:**
- **Quest-check circle:** 28px diameter, 2px border (sketch value, matches `.quest-check`).
- **Row padding:** 12px vertical / 16px (`md`) horizontal, 1px `K.lineSoft` bottom divider between
  rows (sketch `.quest-item` minus the last row).
- **Row internal gap:** 12px between check-circle / text-block / mini-track / reward-amount
  (sketch value).
- **Mini progress track (not-yet-done rows only):** 44px × 6px, pill radius (sketch
  `.quest-mini-track`).
- **Total card, bar-wrap:** 16px top / 16px sides / 4px bottom on the total row; 8px top / 16px
  sides / 16px bottom on the bar-wrap beneath it (sketch values, close to `md`).

**Ring-badges:**
- **Ring diameter:** 160px, with a 14px inset "hole" (sketch `.ring-big`/`.hole` values) —
  matches the visual scale of a "trophy case" hero element, distinct from any existing `K`
  component (no reuse conflict).
- **Tier badge circle:** 46px diameter, 2.5px border (sketch `.tier-badge .circ`) — same family
  as the existing streak-chip circle sizing already used in `ProfileSheet.tsx`.
- **Tier badge row gap:** 8px between the 3 badges (`sm` spacing-scale token, rounded from the
  sketch's 10px — this is inter-element spacing between sibling badges, not a component's own
  intrinsic dimension, so it uses the declared 4px-grid token rather than the raw sketch value).
- **Popover (`.tier-pop`):** padding 8px 12px, 10px border-radius, positioned `bottom: calc(100% +
  8px)` above its badge, `translateX(-50%)` centered (sketch values, verbatim).
- **Week-dot:** 26px × 26px, 8px border-radius (sketch `.week-dot`), 8px gap between the 7 dots
  (`sm` spacing-scale token, rounded from the sketch's 7px — same inter-element-spacing rationale
  as the tier badge row gap above).

**Tap target:** every interactive element this phase (quest-item row if made tappable — it is not,
rows are display-only per D-01..D-05; tier badges; popover backdrop) inherits the existing 44px
minimum touch-target convention (Phase 4.2). Tier badges at 46px already clear this; the invisible
tap-catch area around each badge should be padded to at least 44px if the visual circle alone would
be smaller in a future re-skin — not a concern at the current 46px size.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (row title, ring center label context) | 16px | 700 (`K.fDisp`) | 1.3 |
| Label (row subtitle, reward amount, badge label, popover text, chip text) | 13px | 700 (`K.fBody`/`K.fDisp`) | 1.3 |
| Heading (sheet title, ring center value) | 22px | 900 (`K.fDisp`) | 1.2 |
| Display (total-row coin amount) | 20px | 900 (`K.fDisp`) | 1.2 |

Same 4 sizes (13/16/20/22px) and 2 weights (700/900) as Phase 9.3/9.4/9.5 — reused unchanged so
these two new bodies read as one consistent screen family with the rest of the kid app and with
`segmented-bar`. Notes specific to this phase's new content:

- **Quest-item title** (`.t1`, e.g. `"5 пятёрок за неделю"`) — sketch's 14px rounds into the
  existing Label bucket (13px), NOT a new "15px" bucket; weight 700 (900 only for the strikethrough
  done state would be too heavy against `K.fBody` — keep 700 for both done/not-done, convey "done"
  via strikethrough + color, per D-03/CSS pattern `.quest-item.done .t1`).
- **Quest-item subtitle** (`.t2`, e.g. `"Тир 2 — ещё 3"`) — Label size (13/700) at `K.ink3` (muted),
  matching the sketch's `.t2` faint treatment.
- **Quest reward amount** (`.quest-reward`, e.g. `"+300"`) — Label size (13/700), NOT Display —
  per D-00 the coin amount must read secondary/smaller than the achievement title. Since the type
  scale only has 4 sizes, "smaller/secondary" is achieved through **position + color weight**, not
  a 5th font-size: right-aligned, narrow (46px) column, `K.mangoDeep` when earned / `K.ink3` when
  not yet earned — visually recedes next to the Body-weight title even at the same 13px, exactly
  mirroring how 9.5's penalty hint stayed in the Label bucket rather than inventing a smaller size.
- **Quest total row** — identical treatment to segmented-bar's total row: label Label (13/700)
  `K.ink3`, value Display (20/900) `K.mangoDeep`. Same component, reused verbatim. This total row
  is the quest-checklist body's primary visual anchor — the "payoff moment" analogous to the ring
  center value in the ring-badges body — carried by the Display size/weight jump against the
  smaller Label-bucket rows above it, no new size needed.
- **Ring center value** (e.g. `"+380"`) — sketch's 26px rounds UP into the Heading bucket (22/900)
  rather than Display (20/900): this is the visual focal point of the entire ring-badges body (the
  "payoff moment" of the style, same rationale 9.5 gave for its own total row), so it takes the
  larger of the two prominent sizes already declared — no new size introduced.
- **Ring center label** (`"сейчас"` / "this week") — Label (13/700), `K.ink3`.
- **Tier badge label** (`"Тир 1"`) — sketch's 10.5px rounds into Label (13/700); `K.ink3` when
  not-reached, `K.mangoDeep` when reached (sketch `.tier-badge.reached .lbl`).
- **Tier badge glyph** (🥉🥈🥇, or ⚠ when penalized) — decorative glyph inside the 46px circle,
  ~20px, not part of the 4-size type scale (same treatment as every other emoji glyph in the kid
  app, e.g. the 🚀 sheet-title icon).
- **Popover text** (`.tier-pop`) — sketch's 11.5px rounds into Label (13/700), white text on a
  `K.ink` dark background (see Color section).
- **Week-dot glyph** (Пн/Вт/…) — sketch's 12px/800 rounds into Label (13/700) — do not introduce
  weight 800; use the same 700 already declared for every other Label-bucket element this phase,
  distinguishing "filled" purely by background color (mint) not extra weight.
- **Section note** (best-tier-not-summed explainer, both styles) — Label (13/700). Phase 9.5's own
  explainer note uses plain Label weight (700, its default), not the sketch's raw
  `.section-note { font-weight: 600 }` CSS — that 600 value was never actually adopted by 9.5's
  UI-SPEC and would introduce a 3rd weight into this phase's declared 2-weight system (700/900).
  Reuse 700 here, matching 9.5's real explainer-note weight exactly.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `K.cream` (#FFFDF7) | Page background behind the sheet (unchanged — sheet is an overlay) |
| Secondary (30%) | `K.card` (#FFFFFF) | `BottomSheet` body background, quest-item card background, ring "hole" fill, badge not-reached fill (soft variant), status-chip surfaces |
| Accent (10%) | `K.mango` / `K.mangoDeep` (#FF9F2E / #E07E00) | Reserved for: quest-item reward amounts once earned, the ring's conic-gradient fill arc, tier-badge **reached** state (border + `K.mangoSoft` fill), the streak-chip done state — same "coins/streak-heat/boost" semantic `kidTheme.ts` already documents for `K.mango` |
| Destructive/negative | `K.danger` (#D84C5E) | Reserved for: quest-checklist's 3 grade rows in the penalty-zeroed state (D-15) and ring-badges' 3 grade badges in the penalty-zeroed state (D-15) — never used decoratively elsewhere in either view |

Additional semantic colors, all reused unchanged from the existing palette (no new hex values,
D-16):

- `K.mint` (#12B886) — reserved for: quest-item **done** check-circle fill (`.quest-check` mint
  bg, matching the sketch's `.quest-item.done .quest-check`), the week-dot **filled** state
  (matches the established "done = mint" convention from Phase 9.3/9.4's tile/dot states, and the
  segmented-bar full-week chip's done state).
- `K.sky` (#2F7FE4) — reserved for: the ring-badges "next" tier badge's highlight outline/glow
  (D-09) only — reuses `K.sky`'s documented "focus ring, selected state" semantic as an "aim here
  next" cue, never used decoratively elsewhere in either new view.
- `K.line` / `K.lineSoft` — reserved for: quest-item not-yet-done mini-track background, tier
  badge **not-reached-not-next** state (neutral border/fill, matching every other "not yet" state
  across the kid app), week-dot **not-filled** state.
- `K.ink` (#21314A) — reserved for: the tier-badge popover's solid background (white text on top,
  matching the sketch's `var(--color-text)` dark popover exactly — `K.ink` already IS that dark
  text color, reused here as a surface, not a new token).
- `K.mangoSoft` (#FFEED8) — reserved for: tier badge **reached** state's soft fill (paired with
  `K.mango` border, matches sketch `.tier-badge.reached .circ`).

**Penalty state, both new styles (D-15, extends 9.5's D-05 principle):** identical muted-danger
idiom already established in `BoostDetailSheet.tsx`'s segmented-bar grades block — background
`${K.danger}1F` (~12% alpha), border `1.5px solid ${K.danger}55`, `⚠` glyph, hint text in solid
`K.danger`. Applied to:
- **Quest-checklist:** all 3 grade rows (t1/t2/t3) render in this muted-danger row treatment
  instead of their normal done/not-done state — check-circle shows `⚠` instead of `✓`/count,
  reward amount stays visible but in `K.danger` not `K.mangoDeep`. The `kidBoost.detail.penaltyHint`
  text (reused verbatim from 9.5, not duplicated per-row) appears once, directly below the group of
  3 grade rows.
- **Ring-badges:** all 3 grade badges (🥉🥈🥇) render with `K.danger` border + `${K.danger}1F` fill
  instead of their normal reached/not-reached circle treatment, with the medal glyph replaced by
  `⚠`. `kidBoost.detail.penaltyHint` appears once, directly below the tier-badge row.

This is a **third, mutually exclusive** row/badge state alongside "done" and "not-done" in both new
styles — never combine the danger treatment with the normal mango/mint treatment on the same
row/badge.

Accent reserved for: quest reward amounts (earned only), the ring's fill arc + center value color,
tier-badge reached state, the streak-chip done state (reused from 9.5) — never used decoratively
elsewhere in either screen.

## Interaction Contract — Quest-Checklist (BOOST-04, D-00 through D-05)

This section supplements the standard template — BOOST-04 is fundamentally a data/interaction
requirement, not just a visual one.

### Container

Mount inside the same `BoostDetailSheet.tsx` router, using the identical `BottomSheet` chrome as
segmented-bar (D-14): same title (`kidBoost.detail.title`), same 🚀 icon, same `doneLabel={null}`
(no confirm button — read-only view), same X/scrim/swipe close (no third close mechanism, no
backdrop-tap-to-close deviation for the sheet itself — that behavior is reserved for the in-sheet
popover only, see Ring-Badges section).

### Layout structure (top to bottom, inside the sheet body)

1. **Grade-tier group** — 3 quest-item rows, one per tier (D-01), each `padding: 12px 16px`
   inside a single `K.card` container with `1px K.lineSoft` dividers between rows (sketch `.card`
   wrapping `.quest-item`s):
   - Row 1 (t1): title `questGradeTierTitle` with `{{count}} = boost_grades_t1_count`, reward
     `boost_grades_t1`.
   - Row 2 (t2): title `questGradeTierTitle` with `{{count}} = boost_grades_t2_count`, reward
     `boost_grades_t2`.
   - Row 3 (perfect/t3): title `questGradePerfectTitle`, reward `boost_grades_t3`.
   - Each row's own "reached" condition is evaluated **independently** of the others (not the
     sequential best-tier-wins logic used for the segmented-bar's single fill %) — row 1 reached
     when `topGradeCount >= boost_grades_t1_count`, row 2 when `topGradeCount >=
     boost_grades_t2_count`, row 3 (perfect) when `goodGradeCount === topGradeCount && gradedDays
     >= boost_grades_perfect_days` — all three gated on `!hasPenaltyGrade` (see penalty state
     below).
   - **D-03 (binding):** when a higher-count row is reached, lower-count rows also render
     `done` (checkmark + strikethrough amount) even though only the higher tier's coins actually
     count toward `week.total` — reuse `.quest-item.done` verbatim, no third "superseded" visual
     state.
   - Not-yet-done rows show the 44×6px mini-track at `topGradeCount / countThreshold` fill (t1/t2)
     or a static empty track with `questGradePerfectSubProgress` text (t3, since "perfect" isn't a
     simple count fraction).
   - **Penalty state (D-15):** when `hasPenaltyGrade` is true, all 3 rows render the shared
     muted-danger row treatment (see Color section) instead of their normal done/mini-track state;
     `kidBoost.detail.penaltyHint` appears once beneath the group, not per-row.
2. **`kidBoost.detail.questNote`** (D-04, binding) — sits directly beneath the grade-tier group,
   Label size, `K.ink3` — the "best tier counts, not summed" clarification, positioned near the
   rows it explains rather than only at the very bottom of the sheet.
3. **Consistency group** — 3 more quest-item rows in a second `K.card` container, same row shape:
   - Full-week row: `questFullWeekTitle`, reward `boost_full_week`, done when `filledDays >= 7`
     (subtitle reuses `fullWeekDone`/`fullWeekPending` verbatim as the row's `.t2` line).
   - Streak×2 row: `questStreak2Title`, reward `boost_streaks_2`, done when
     `streaksAtThreshold >= 2`.
   - Streak×3 row: `questStreak3Title`, reward `boost_streaks_3`, done when
     `streaksAtThreshold >= 3`.
   - Same D-03 superseded-still-checked rule applies between streak×2/streak×3 (best-wins,
     non-summed, per D-02).
4. **Combined total row** (mandatory, matches segmented-bar's total row component exactly) — label
   `kidBoost.detail.totalLabel`, value `boost.week.total` (the real, non-summed total — **not**
   the arithmetic sum of the 6 listed row amounts, which is exactly why step 2's note exists). This
   total row is the quest-checklist body's primary visual anchor (see Typography section) — the
   moment the kid's eye should land on last, mirroring the ring center value's role in the
   ring-badges body.
5. **Total progress bar** (sketch-prescribed composition, D-13 — keep this style's own validated
   look) — a single bar beneath the total row, `linear-gradient(90deg, K.mango, K.berry)` fill at
   `week.total / week.max * 100`, with `boost.week.nextLabel` reused verbatim as the caption below
   it (no second parallel copy-generation path — same reuse discipline as segmented-bar's D-04
   hint text).

### Data → visual mapping

| Visual element | Source (`lib/kid/boost-rules.ts` / `lib/kid/boost.ts`) |
|---|---|
| Row 1/2 reached + mini-track fill | `WeeklyGradeStats.topGradeCount` vs. `BoostSettings.boost_grades_t1_count`/`t2_count` |
| Row 3 (perfect) reached | `WeeklyGradeStats.goodGradeCount === topGradeCount && gradedDays >= boost_grades_perfect_days` |
| All 3 grade rows' penalty state | `WeeklyGradeStats.hasPenaltyGrade` |
| Full-week row reached | `WeeklyConsistencyStats.filledDays >= 7` |
| Streak×2/×3 rows reached | `WeeklyConsistencyStats.streaksAtThreshold >= 2` / `>= 3` |
| Combined total | `WeeklyBoostResult.total` (== `boost.week.total`) |
| Total bar fill % + caption | `WeeklyBoostResult.total / WeeklyBoostResult.max`, `WeeklyBoostResult.nextLabel` |

## Interaction Contract — Ring + Tier Badges (BOOST-05, D-06 through D-12)

### Container

Same `BottomSheet` chrome as segmented-bar and quest-checklist (D-14) — identical title/icon/close
behavior at the sheet level. The tier-badge popover introduced below is a distinct, smaller
interactive element **inside** the sheet body — its own close rules (D-11) are independent of and
do not loosen the sheet's own explicit-close rule.

### Layout structure (top to bottom, inside the sheet body)

1. **Ring** — 160px conic-gradient ring (`conic-gradient(K.mango {pct}deg, K.line 0deg)`), 14px
   inset white "hole" (`K.card`) showing:
   - Center value: `+{week.total}` — Heading size (22/900), `K.mangoDeep`.
   - Center label: `kidBoost.detail.ringNowLabel` — Label size (13/700), `K.ink3`.
   - **Fill % (D-08, binding):** `week.total / week.max * 100` — the **exact same** total/max
     the inline `BoostMeter` already displays. No new/blended progress metric; this is the same
     number the kid saw on the meter before tapping in.
2. **Tier badge row** — 3 badges (🥉🥈🥇), 46px circles, 8px gaps (`sm` token, see Spacing
   section), representing **grade tiers only** (D-06 — not all 5 non-summed tiers, matches the
   validated sketch composition):
   - Badge states (mutually exclusive):
     - **Reached:** `K.mango` border + `K.mangoSoft` fill, `K.mangoDeep` label.
     - **Next (immediately-next unreached, D-09):** `K.sky` outline/glow highlight — a distinct
       "aim here next" cue beyond the sketch's plain binary reached/grey. Exact treatment
       (outline vs glow vs pulse) is implementer's discretion within the established
       reduced-motion double-guard (any animated version must have a static fallback).
     - **Not-reached, not-next:** `K.line` border + `K.lineSoft` fill (sketch's plain default).
     - **Penalized (D-15):** `K.danger` border + `${K.danger}1F` fill, `⚠` glyph replacing the
       medal — applies to all 3 grade badges simultaneously when `hasPenaltyGrade` is true,
       mutually exclusive with the other 3 states.
   - Tapping a badge opens its popover (D-10/D-11 below); the badge's own visual state (reached/
     next/not-reached/penalized) is independent of whether its popover is currently open.
3. **Tier-badge popover** (`.tier-pop`) — positioned above its badge, `K.ink` background, white
   text, Label size (13/700):
   - **Single-open-at-a-time (D-10):** tapping a different badge closes whichever popover is
     currently open before opening the new one (sketch's `.tier-badge.open` toggle class, `else`
     branch always clears all `.open` classes first).
   - **Tap-outside/backdrop also closes (D-11):** in addition to tapping the same badge again to
     close it — a lightweight contextual dismiss, **not** the `BottomSheet`'s own explicit-close-
     only rule (that rule is unchanged for the sheet itself, per 9.4/9.5 precedent). Implement as
     a transparent full-sheet-body backdrop `onClick` that closes an open popover if one exists,
     layered beneath the badges themselves (so badge taps still register normally).
   - **Copy differs by state (D-12):**
     - Reached (any of the 3 tiers, including the already-maxed top tier — **no special "maxed
       out" branch**, same template): `ringPopReachedTitle` (t1/t2) or
       `ringPopPerfectReachedTitle` (t3) as the headline, `ringPopCoinsEarned` as a visually
       secondary line beneath it.
     - Not-yet-reached: `ringPopNextTitle` (t1/t2, interpolated with the count still needed) or
       `ringPopPerfectNextTitle` (t3) as the headline, `ringPopCoinsPending` as the secondary
       line.
     - Penalized state (D-15): badge itself already signals penalty visually; popover content for
       a penalized badge reuses the **not-yet-reached** template (the grades bonus genuinely isn't
       earned this week) — do not invent a 5th popover variant for "penalized."
4. **Consistency section** (D-07) — a separate `K.card` block below the tier-badge row:
   - **7-dot week strip:** one `.week-dot` per weekday (Пн…Вс), 26×26px, `K.mint` fill when that
     day was saved, `K.lineSoft` when not. `aria-label={t('kidBoost.detail.ringWeekDotsLabel')}`
     on the strip container.
   - **Streak status chip** — reuses `kidBoost.detail.streakDone`/`streakPending` **verbatim**
     (same copy/color as segmented-bar's existing chip, D-07 binding) — mango when done, neutral
     when not. Layout (directly under vs. beside the dot strip) is implementer's discretion, as
     long as both are visible together without scrolling within the card.
   - This section does **not** duplicate the tier badges' function — it represents the
     full-week + streak consistency bonus only, kept visually separate from the grade tiers per
     D-06/D-07's explicit "don't overload the dots with a second meaning."

### Data → visual mapping

| Visual element | Source (`lib/kid/boost-rules.ts` / `lib/kid/boost.ts`) |
|---|---|
| Ring fill % + center value | `WeeklyBoostResult.total / WeeklyBoostResult.max`, `WeeklyBoostResult.total` |
| Tier badge 1/2/3 reached | `WeeklyGradeStats.topGradeCount >= boost_grades_t1_count/t2_count`, perfect condition for t3 (same as quest-checklist rows 1-3) |
| Tier badge penalty state | `WeeklyGradeStats.hasPenaltyGrade` |
| Tier badge "next" (D-09) | the lowest-indexed tier among the 3 that is not yet reached (none, if all 3 reached) |
| Popover coin amounts | `boost_grades_t1`/`t2`/`t3` |
| Week-dot fill (per day) | needs a **per-day filled boolean array** for the current week, not just the existing `filledDays` count |
| Streak chip state | `WeeklyConsistencyStats.streaksAtThreshold >= 2` (identical source to segmented-bar's chip) |

**Binding integration note (not a new decision, flagged in `09.6-CONTEXT.md`):** the current
`WeeklyConsistencyStats`/`BoostDetailView` shape exposes only a `filledDays` **count** (0-7), not a
per-day array — the 7-dot strip needs to know *which* days were filled, not just how many. This
UI-SPEC requires that additive data extension (or an equivalent sibling read, e.g. from the
existing week-of-days query already used elsewhere for streak calculation) before this layout can
render for real; it is an implementation task, not a new visual decision.

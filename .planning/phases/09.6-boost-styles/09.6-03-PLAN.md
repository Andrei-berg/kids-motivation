<objective>
Complete the `BoostDetailSheet` style router with the second and final new body: `ring-badges`, a
160px conic-gradient ring showing the current week total, 3 tappable grade-tier badges each opening
a single-open-at-a-time popover, and a separate 7-dot week strip + streak chip for the consistency
side (BOOST-05).

Purpose: BOOST-05's success criterion is "one ring shows the current total and tappable tier badges
open a popover explaining what's needed for the next tier" — this plan is the entire ring-badges
implementation and the point at which the phase's style router becomes a true 3-way branch
(`quest-checklist` / `ring-badges` / `segmented-bar`), closing D-13's "each style keeps its own
sketch-prescribed composition."
Output: `RingBadgesBody` function (ring, tier badges, popover, week-dot strip, streak chip) plus the
completed 3-way branch in the main `BoostDetailSheet` component.

Why this is its own plan, after 09.6-02: same file as the quest-checklist plan (file-overlap forces
sequential waves), and `ring-badges` carries its own interactive state (`openTierId`) and a
tap-outside-to-close backdrop that quest-checklist has no equivalent of — bundling both bodies in one
plan would exceed the ~50% context budget for a single execution plan (same rationale as 09.6-02's
own split from this plan, stated there).
</objective>

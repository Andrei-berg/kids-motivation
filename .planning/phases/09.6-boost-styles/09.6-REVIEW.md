## Warnings

### WR-01: Unguarded `boost.week.total / boost.week.max` division can render `NaN%` width

**File:** `components/kid/boost/BoostDetailSheet.tsx:448`
**Issue:** `QuestChecklistBody`'s total progress bar computes
`width: \`${(boost.week.total / boost.week.max) * 100}%\`` with no guard against
`boost.week.max === 0`. `boost.week.max = boost_grades_t3 + boost_full_week + boost_streaks_3`
(`lib/kid/boost-rules.ts`), all three of which are per-family `wallet_settings` values a parent
can legitimately set to `0` to disable the weekly boost feature entirely. In that case
`total` is also `0`, so the division is `0/0 = NaN`, producing the CSS value `"NaN%"` — invalid,
silently dropped by the browser, leaving the bar in an inconsistent/undefined width rather than
the deliberately-computed `0%` the sibling component produces for the exact same fraction three
call sites away:

```ts
// RingBadgesBody, line 475 — guarded
const ringPct = boost.week.max > 0 ? Math.round((boost.week.total / boost.week.max) * 360) : 0
```

**Fix:** Apply the same guard in `QuestChecklistBody`:
```tsx
width: `${boost.week.max > 0 ? (boost.week.total / boost.week.max) * 100 : 0}%`,
```
Consider factoring both call sites into a single `pctOf(total, max)` helper (e.g. next to
`clampPct` in `lib/kid/boost-detail.ts`) so the guard can't be forgotten a third time when a
future style body is added.

## Info

### IN-01: Translated string used as React list key

**File:** `components/kid/boost/BoostDetailSheet.tsx:388`
**Issue:** `consistencyRows.map((row, i) => ... key={row.title})` uses the already-`t()`-translated
title string as the React key, instead of a stable identifier (e.g. the untranslated row
label like `'fullWeek' | 'streak2' | 'streak3'`, or simply the index `i`, which is safe here
since the list is a fixed-length literal array rebuilt fresh each render). If a future locale
ever produces two identical translated strings for two different rows, or if `useT` returns a
transient placeholder while loading, React key collisions would cause incorrect reuse of DOM
nodes/component state between rows. The parallel `gradeRows.map` two blocks above correctly
keys on `row.tier.index` — the pattern already exists in this same file and should be reused.
**Fix:**
```tsx
{consistencyRows.map((row, i) => (
  <div key={['fullWeek', 'streak2', 'streak3'][i]} ...>
```

### IN-02: Ring-badge popover has no ARIA relationship or keyboard dismissal

**File:** `components/kid/boost/BoostDetailSheet.tsx:577-613`
**Issue:** The tier badge `<button>` sets `aria-expanded` correctly, but the popover content
it toggles has no `id`/`aria-controls`/`aria-describedby` link back to the button and no
`role` (e.g. `role="tooltip"` or `role="dialog"`), so assistive tech has no reliable way to
associate the button with the text that appears, or to announce it as it mounts. There is also
no `Escape`-key handler to dismiss it — only a re-tap of the badge or a tap on the transparent
backdrop closes it, which excludes keyboard-only users entirely (the backdrop is a bare `<div
onClick>` with no keyboard equivalent, and the badges are the only focusable elements in the
popover's dismiss path).
**Fix:** Give the popover an `id`, reference it from the button via `aria-controls`, add
`role="status"` or `role="tooltip"`, and add a `onKeyDown` handler on the button (or a
document-level listener while `openTierId !== null`) that closes the popover on `Escape`.

### IN-03: New interactive bodies have no component-level test coverage

**File:** `components/kid/boost/BoostDetailSheet.tsx` (whole file), `tests/boost-detail.test.ts`
**Issue:** `tests/boost-detail.test.ts` thoroughly covers the pure `buildBoostDetail` view-model
(25 cases), but the two new rendering bodies added this phase — `QuestChecklistBody` and,
especially, `RingBadgesBody` (which owns non-trivial interaction state: single-open-at-a-time
popover toggling, backdrop-dismiss, penalized-badge override of the "next" highlight) — have no
component tests at all. A regression in the toggle logic (e.g. the `WR-01` bug above, or a
future change to `openTierId` handling) would not be caught by the existing test suite.
**Fix:** Add a small React Testing Library suite for `RingBadgesBody`/`QuestChecklistBody`
covering: tapping a badge opens its popover and closes any other open one; tapping the backdrop
closes it; a penalized week never marks any badge/row as `reached` even when the underlying
`tiers[i].reached` values would otherwise be true.

### Build failure diagnosis (not a code defect)

`dig`/`nslookup fonts.googleapis.com` resolves to `198.18.0.143` — the sandbox's filtered-egress
IP range — and a direct `curl` to that host fails with `SSL_ERROR_SYSCALL` (connection reset
during the TLS handshake) on every one of 8 retries over several minutes. By contrast,
`fonts.gstatic.com` (same range, `198.18.0.144`) accepts the TLS connection (returns a plain 404
on a bare `GET /`), and `github.com`/`supabase.com`/`google.com` all return `200`. This is a
sandbox-specific allowlist gap on the `fonts.googleapis.com` CSS-manifest endpoint specifically
(the one `next/font/google` hits first to resolve `Bitter`/`Rubik`/`JetBrains Mono`'s actual
`.woff2` URLs), not a general network outage and not caused by any diff in this plan (which only
touches two `project-docs/*.md` files) or any prior 09.6 plan (`next/font/google` usage in
`app/layout.tsx` is untouched this phase). The same `.env.local`-must-be-copied-into-a-fresh-
worktree gap documented in 09.6-02/03/04's summaries applies identically here (worked around by
copying `.env.local` in, confirmed never staged via `git status --short`, then deleting it + the
partial `.next/` output before committing) — but unlike those three plans, this session's
`fonts.googleapis.com` block did not resolve after retries, so `npm run build`'s green status
could not be independently re-confirmed in this sandbox run. Recommend the operator (or the
orchestrator, outside this sandboxed execution) run `npm run build` once from an unrestricted
network to close this one gate for the record — `tsc`/`lint`/`test` all independently confirm the
TypeScript/logic/runtime-behavior surface is sound.

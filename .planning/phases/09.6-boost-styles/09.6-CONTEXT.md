# Phase 9.6: boost-styles - Context

**Gathered:** 2026-09-20
**Status:** Ready for planning

<domain>
## Phase Boundary

Build the two remaining `boost_style` options — `quest-checklist` and `ring-badges` — as real,
selectable weekly-boost detail-view bodies plugged into the exact same architecture Phase 9.5
built for `segmented-bar`: the same 3 tap entry points (Day hero full/compact `BoostMeter`,
`ProfileSheet`'s `BoostMeter`), the same `BottomSheet` container, and the same real
`BoostDetailView` data (`lib/kid/boost-detail.ts`'s `buildBoostDetail`) — no new coin math, no
new data model, no changes to `segmented-bar` itself.

This phase also finishes wiring the `boost_style` preference into a real 3-way picker:
`ProfileSheet`'s "Style" section currently renders a single hardcoded always-active
"segmented-bar" button (mirroring Phase 9.3/9.4/9.5's single-real-option-per-phase pattern) —
it becomes a real 3-option `role="radio"` group, same shape as the `fill_style` picker above it.
`app/kid/actions/boost-style.ts` already validates and accepts all 3 style values (unlike
`fill_style`'s Phase-9.3-era scope guard, this action was deliberately built with no guard to
remove — confirmed still true, no server-side change needed).

Out of scope: milestone tiers (`/kid/achievements`), the inline `BoostMeter`'s own shape
(stays unchanged), and any new economy/reward mechanic (loot-box/crate, raised and deferred
again in Phases 9.4/9.5 — not re-discussed this session, no new deferral needed).

</domain>

<decisions>
## Implementation Decisions

### Motivation framing (applies to both new styles)
- **D-00:** Row/badge/popover copy leads with the achievement or condition (what was done —
  e.g. "5 пятёрок за неделю"), with the coin amount shown secondary and visually smaller —
  never the headline of a row, badge, or popover. Explicit user guidance: coins are a tool,
  not the goal of the app, and the UI for these two styles must reinforce that rather than
  putting money first. This directly extends PROJECT.md's existing philosophy ("дети не
  просто получают награды — они их зарабатывают... это не игра") into copy/layout choices for
  this phase specifically.

### Quest-checklist row breakdown
- **D-01:** Grade-tier condition gets **3 separate rows** — one per non-summed tier (t1/t2/t3),
  matching the sketch's own example rows and BOOST-04's plural "grade-tier thresholds."
- **D-02:** Consistency side gets **3 rows** too, for the same granularity reason: full-week
  completion (binary) + streak×2 + streak×3 — streak is itself 2 non-summed tiers, same
  treatment as the grades rows rather than collapsing it into one combined row.
- **D-03:** When a higher tier is reached, the now-surpassed lower-tier row(s) still show as
  checked/done — checkmark + strikethrough amount, reusing the sketch's `.quest-item.done`
  style verbatim. No third "superseded" visual state.
- **D-04:** An explicit "лучший тир засчитывается, не суммируется" note sits near the
  grade/streak row groups (per `progress-and-boost.md`'s own warning about this exact risk).
  The bottom "combined total" row shows the real `week.total` — identical value/logic to
  segmented-bar's total row — which will generally NOT equal the sum of the individually
  listed row amounts; the note exists specifically so that mismatch doesn't read as a bug.

### Ring-badges tier mapping
- **D-06:** Tier badges represent **grade tiers only** (3 badges: t1/t2/t3) — matches the
  validated sketch composition (variant C), not all 5 non-summed tiers (grades + streak).
- **D-07:** Consistency (full-week + streak) is shown via the sketch's **7-dot week strip**
  (one dot per day, filled = day saved) plus a **small streak status chip** alongside/below it,
  reusing segmented-bar's existing chip pattern/copy (`kidBoost.detail.streakDone`/
  `streakPending`) rather than overloading the dots with a second meaning.
- **D-08:** Ring fill percentage = `week.total / week.max` — the exact same total/max the
  inline `BoostMeter` already displays, so the ring visually mirrors what the kid saw before
  tapping in. No new/blended progress metric.
- **D-09:** The immediately-next (not-yet-reached) badge gets a distinct highlight
  (outline/glow) beyond the sketch's plain binary reached/grey — a visual "aim here next" cue.

### Popover interaction
- **D-10:** Single-open-at-a-time — tapping a different badge closes whichever popover is
  currently open (matches the sketch's `.tier-badge.open` toggle class).
- **D-11:** Tap-outside/backdrop also closes an open popover, in addition to tapping the same
  badge again. This is a lightweight contextual popover, not the `BottomSheet`'s own
  explicit-close-only rule — that rule is unchanged for the sheet itself (9.4/9.5 precedent).
- **D-12:** Popover copy differs by state, per D-00's framing: a **reached** badge says what
  was earned, behavior-first (e.g. "5 пятёрок за неделю — заработано!"), coin amount shown
  after/smaller; a **not-yet-reached** badge says what's needed (e.g. "ещё 2 пятёрки до этого
  тира"), same secondary-amount treatment. The already-maxed top tier uses the same "reached"
  template — no special extra "maxed out" framing/copy branch.

### Visual consistency vs sketch fidelity
- **D-13:** Each style keeps its **own sketch-prescribed composition** — no shared gradient
  hero-card wrapper forced across all three. Quest-checklist stays a plain list; ring-badges
  keeps its ring+badges+dot-strip layout; segmented-bar (9.5) keeps its mango→berry hero card
  unchanged. The three styles are deliberately meant to look/feel different — that's the point
  of offering a choice, not a shared-chrome reskin.
- **D-14:** All three styles share the same `BottomSheet` title/icon ("Буст недели" / 🚀,
  `kidBoost.detail.title`) — same underlying feature, same recognizable chrome, only the body
  differs per style.
- **D-15:** Penalty-grade state (a single penalty grade zeros the whole grades bonus this week)
  gets the same distinct muted/red treatment in both new styles as segmented-bar's existing
  D-05 (Phase 9.5): quest-checklist's 3 grade rows all show the red/muted "penalty zeroed this"
  state (not just plain unchecked); ring-badges' 3 grade badges show the same red/muted state
  (not plain grey "not reached"). Same transparency principle, extended to both new styles.
- **D-16:** Standard `K` design-token reuse throughout both new styles (K.mint, K.mango,
  K.danger, K.card, K.line, etc.) — no new colors introduced from the sketch's raw CSS vars.

### Claude's Discretion
- Exact spacing/typography of the quest-checklist rows and the ring-badges layout beyond the
  sketch's `.quest-item`/`.ring-big`/`.tier-badge` CSS — implementer's call within the `K`
  palette.
- Exact wording of the "best tier counts, not summed" note (D-04) and the behavior-first
  popover copy (D-12) — implementer's call within existing i18n/copy patterns, must honor D-00.
- Exact highlight treatment for the "next" badge (D-09) — outline vs glow vs pulse,
  implementer's call within the reduced-motion double-guard pattern already established.
- Whether the streak status chip (D-07) sits directly under the dot strip or beside it —
  implementer's call on layout, as long as both are visible together.

</decisions>

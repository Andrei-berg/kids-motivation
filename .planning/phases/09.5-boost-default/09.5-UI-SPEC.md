# Phase 9.5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**No RESEARCH.md exists for this phase** (same as 9.3/9.4 — `09.5-CONTEXT.md` was judged detailed
enough to skip a separate technical-research pass). Every stack/pattern decision below comes from
the existing codebase (already cited file-by-file in `09.5-CONTEXT.md`'s `<canonical_refs>`), the
validated sketch HTML
(`.claude/skills/sketch-findings-kids-motivation/sources/003-weekly-boost/index.html`, `#variant-a`
only — `#variant-b`/`#variant-c` belong to Phase 9.6), and `lib/kid/boost-rules.ts` as the real data
source (BOOST-06).

**Continuity requirement:** this phase reuses Phase 9.4's exact `BottomSheet` primitive (D-02) and
must stay visually consistent with the established kid design system — same `K` palette, same type
scale, same reduced-motion guard idiom. This UI-SPEC reuses Phase 9.3/9.4's Design
System/Spacing/Typography sections verbatim and adds new sections only for what's actually new
this phase: the boost detail sheet's segmented dual-bar content, the `boost_style` picker, and the
`BoostMeter`-becomes-tappable interaction.

All design decisions referenced below (D-01..D-10) are from `09.5-CONTEXT.md` — this document does
not re-litigate them, it translates them into an executable visual/interaction contract.

## Spacing Scale

Declared values (must be multiples of 4) — identical to Phase 9.3/9.4's declared scale, reused
unchanged:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, chip internal gaps |
| sm | 8px | Sub-bar block gaps, chip row gap |
| md | 16px | Sheet horizontal padding, hero-card margin |
| lg | 24px | not used this phase |
| xl | 32px | not used this phase |
| 2xl | 48px | not used this phase |
| 3xl | 64px | not used this phase |

### Spacing-scale exceptions

None — every declared token above is a strict multiple of 4. Where the sketch's raw CSS used a
non-multiple value, round to the nearest declared token rather than copying verbatim (matches
Phase 9.4's precedent), e.g. sketch's `.boost-hero { padding: 18px 18px 16px }` → `md` (16px)
all around.

### Component intrinsic sizing (pre-existing/sketch-validated, not new spacing tokens)

- **Hero card radius:** `20px` (sketch value, close to but distinct from the standard 18px kid
  card radius — kept as-is, matches the existing inline `BoostMeter`'s own `14px` radius family of
  "rounded promo card" shapes rather than a plain list card).
- **Sub-bar track height:** `10px` (sketch value, matches `BoostMeter`'s own inline bar height
  exactly — `components/kid/design/atoms.tsx` line ~497 uses `height: 8`; this detail view's bars
  are slightly taller per the sketch, acceptable as a distinct "detail" weight).
- **Sub-bar fill transition:** `width .8s cubic-bezier(.2,.9,.3,1.1)` (sketch's exact easing,
  matches `BoostMeter`'s own `transition: width 0.9s cubic-bezier(.2,.9,.3,1.2)` closely enough to
  read as the same family of motion — use the sketch's `.8s`/`(.2,.9,.3,1.1)` values verbatim for
  the two new sub-bars).
- **Status chip:** pill shape (999px radius), min-height 28px, matching the existing streak-chip
  pattern already in `ProfileSheet.tsx` (`STREAK_META` chips, `padding: '7px 12px'`) — reuse that
  exact chip shape/padding for the two new "7/7 дней" / "стрик×N" chips (D-06).
- **Tap target (BoostMeter wrapper):** the existing `BoostMeter` card is already well over the
  44px minimum touch target in both `compact` and full variants — wrapping it in a `<button>` (or
  `role="button"` div) adds no new sizing constraint, just an interactive affordance.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (sub-bar head label, chip text) | 16px | 700 (`K.fDisp`) | 1.3 |
| Label (hint text, chip micro-copy, seg-head right-aligned status) | 13px | 700 (`K.fBody`/`K.fNum`) | 1.3 |
| Heading (sheet title) | 22px | 900 (`K.fDisp`) | 1.2 |
| Display (total-row coin amount) | 20px | 900 (`K.fDisp`) | 1.2 |

Same 4 sizes (13/16/20/22px) and 2 weights (700/900) as Phase 9.3/9.4 — reused unchanged so this
new surface reads as one consistent screen family with the rest of the kid app. Notes specific to
this phase's new content:

- **Sheet title** (`"🚀 Буст недели"`) → Heading (22/900), same treatment as `BottomSheet`'s
  existing `title` prop styling — no override needed, the component already renders at this size.
- **Sub-bar head** (`.seg-head`, e.g. `"📚 Оценки"` / `"2 из 3 тиров"`) → the sketch's 12.5px
  rounds into the existing Label bucket (13px), not a new size. Left side (category label) renders
  at Body weight visually via bold 700, but stays in the 13px Label size bucket to match the
  sketch's proportions relative to the 22px title.
- **Sub-bar hint** (`.seg-hint`, e.g. `"Ещё 2 пятёрки → Тир 3 (+500 вместо +300)"`) → Label
  (13/700) at reduced opacity (`0.92`, sketch value, kept as a CSS `opacity` not a new color).
- **Total row amount** (D-07, e.g. `"+380 🪙"`) → Display (20/900), same size class as the
  inline `BoostMeter`'s own `+{earned} 🪙` value (`atoms.tsx` line ~495 uses 12px for that
  specific compact instance — the **detail view's** total row is deliberately larger/more
  prominent at Display size since it's the payoff moment of opening the sheet).
- **Status chips** (`"7/7 дней"` / `"стрик×2"`) → Label (13/700), matching `ProfileSheet`'s
  existing streak-chip text size exactly.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `K.cream` (#FFFDF7) | Page background behind the sheet (unchanged — sheet is an overlay) |
| Secondary (30%) | `K.card` (#FFFFFF) | `BottomSheet` body background, status-chip surfaces |
| Accent (10%) | `linear-gradient(135deg, K.mango, K.berry)` | Reserved for: the boost hero card background only (one instance per sheet open) — matches the inline `BoostMeter`'s own bar gradient (`atoms.tsx` line ~499), so the detail view reads as "the same object, zoomed in," not a new visual language |
| Destructive/negative | `K.danger` (#D84C5E) | Reserved for: the grades sub-bar's penalty-disqualified state only (D-05) — never used decoratively elsewhere in this view |

Additional semantic colors, all reused unchanged from the existing palette (no new hex values):

- **White (`#fff`) on the gradient hero card** — sub-bar tracks (`rgba(255,255,255,0.28)`, sketch
  value) and fills (`#fff` solid) live *inside* the mango→berry gradient card, matching the
  sketch's variant-A exactly. This is a white-on-color idiom, not a new named token — do not
  introduce a `K.white` constant, use the literal `#fff`/`rgba(255,255,255,alpha)` as the sketch
  does (same pattern already used for the hero card's own text/labels).
- `K.mint` (#12B886) — reserved for: the "7/7 дней" status chip's **done** state only (fill +
  border), matching the established "done = mint" convention from Phase 9.3/9.4's tile/dot states.
- `K.mango`/`K.mangoDeep` (#FF9F2E/#E07E00) — reserved for: the "стрик×N" status chip's **done**
  state (streak = "heat," per `kidTheme.ts`'s own comment "coins, streak heat, weekly-boost
  meter"), and the entry-point tap affordance (no new color, the `BoostMeter` itself already uses
  this family).
- `K.line`/`K.lineSoft` — reserved for: both status chips' **not-done** state (neutral border/fill,
  matching every other "not yet" state across the kid app — never colored decoratively).

**Grades sub-bar penalty state (D-05, new this phase):** when `hasPenaltyGrade` is true, replace
that `seg-block`'s white-track/white-fill treatment with a **muted danger panel**: background
`${K.danger}1F` (≈12% alpha), border `1.5px solid ${K.danger}55`, border-radius 12px, padding 8px
— matching the established `${K.danger}14`/`${K.danger}40` soft-surface idiom already shipping in
`KidDayFillForm.tsx`'s error banner and Phase 9.4's tile loss-tint. Inside this panel: a ⚠ glyph,
the seg-head label, and the hint text in solid `K.danger` — **the track itself renders at a fixed
~40% muted-red fill width (not 0%, not the real tier fraction)** so it never reads as "empty/no
progress," per D-05's explicit "never a plain 0%" requirement. This is a **third, mutually
exclusive** grades-sub-bar state alongside "normal progress" (white fill, gradient card) and
"tier-3 maxed" (white fill at 100%) — never combine the danger panel with the gradient-card
treatment in the same render.

Accent reserved for: the hero-card gradient (whole-card background, once per sheet), the two
sub-bar fills (white-on-gradient), the two status-chip done-states (mint / mango) — never used
decoratively elsewhere on this screen.

## Interaction Contract — Segmented-Bar Detail View (D-01 through D-08)

This section supplements the standard template — BOOST-02/03 are fundamentally interaction/data
requirements, not just visual ones.

### Entry points (D-01)

All three existing `BoostMeter` render sites become tappable, opening the identical detail sheet:

1. `components/kid/ProfileSheet.tsx` (~line 145) — the profile sheet's own `BoostMeter` mount.
2. `app/kid/(app)/day/page.tsx` (~line 335) — Day hero, full variant.
3. `app/kid/(app)/day/page.tsx` (~line 404) — Day hero, compact variant.

Wrap each mount in an interactive element (`<button type="button">` preferred over a `div` with
`role="button"` for built-in keyboard/focus support) with `aria-label={t('kidBoost.detail.openLabel')}`.
The `BoostMeter` component itself (`atoms.tsx` lines 474-509) stays visually byte-for-byte
unchanged — no new `onClick` prop added *inside* the component; the tap handler wraps it from the
outside at each call site. No visual affordance (no chevron/hint icon) is added to the meter itself
— per CONTEXT.md's explicit "inline meter itself stays visually unchanged."

### Container (D-02, D-03)

Reuse `components/kid/day-fill/BottomSheet.tsx` exactly as built in Phase 9.4 — same props shape
(`open`, `title`, `icon`, `onClose`, `closeLabel`, `doneLabel`, `children`). This phase's usage:

```
<BottomSheet
  open={boostDetailOpen}
  title={t('kidBoost.detail.title')}
  icon="🚀"
  onClose={() => setBoostDetailOpen(false)}
  closeLabel={t('kidFillForm.sheetClose')}
  doneLabel={null}  // no explicit "Готово" button — the whole view is read-only, X/scrim/swipe close it (D-03)
>
  {/* segmented-bar body, see Layout below */}
</BottomSheet>
```

No `doneLabel` button — this view has nothing to confirm/save, so per D-03 the only close paths
are the X button and the scrim tap/swipe-down `BottomSheet` already provides. Do not add a third
close mechanism.

### Layout structure (top to bottom, inside the sheet body)

1. **Hero card** — `border-radius: 20px`, `padding: 16px` (md), `background: linear-gradient(135deg, K.mango, K.berry)`, `color: #fff`. Contains, stacked with `sm` (8px) gaps between blocks:
   - Grades sub-bar block (label + track + hint) — see below.
   - Consistency sub-bar block (label + track + two status chips) — see below.
2. **Total row** (D-07) — outside the hero card, directly below it, `padding: 8px 4px`: left side
   `kidBoost.detail.totalLabel` in Label size, right side the coin amount in Display size/`K.mangoDeep`
   color — value is `boost.week.total`, the **exact same number** already shown on the inline
   `BoostMeter` for this child (no independent recomputation).
3. **Explainer note** (`kidBoost.detail.note`) — Label size, `K.ink3`, below the total row, matching
   the sketch's `.section-note` treatment.

### Grades sub-bar (D-04, D-05)

- **Head row:** left = `kidBoost.detail.gradesLabel` ("📚 Оценки"), right = current progress
  status text (implementer's call on exact phrasing, e.g. reuse/adapt `WeeklyGradeStats.topGradeCount`
  vs. the active tier's count threshold — not separately mandated by CONTEXT.md beyond "own hint
  text" in BOOST-03).
- **Fill logic (D-04, binding):** fractional, not stepped —
  `pct = min(100, topGradeCount / nextThresholdCount * 100)` where `nextThresholdCount` is
  whichever of `boost_grades_t1_count` / `boost_grades_t2_count` / (perfect-day equivalent) is the
  *next unreached* threshold, read live from `lib/kid/boost-rules.ts`'s `BoostSettings` — **never**
  a stepped 0/33/66/100% tier-only fill. When the top tier is already reached, fill = 100%.
- **Hint text:** reuse the existing `WeeklyBoostResult.nextLabel`/`gradesBoost()`'s `next` string
  logic (already computes the correct "ещё N пятёрок → +X" copy) — do not write a second parallel
  copy-generation path.
- **Penalty state (D-05):** see Color section above — muted danger panel replaces the normal
  white-on-gradient treatment for this block only, fixed ~40% muted fill (never literal 0%),
  `kidBoost.detail.penaltyHint` text, ⚠ glyph. This state is mutually exclusive with the normal
  fractional-fill state.

### Consistency sub-bar (D-06)

- **Head row:** left = `kidBoost.detail.consistencyLabel` ("🔥 Стабильность"), right = combined
  status text (implementer's call, e.g. "X из 2 бонусов").
- **Track:** one `seg-track` split into **two independent zones** side by side with a small gap
  (2-4px, implementer's call) between them — left zone = full-week condition, right zone = streak
  condition. Each zone fills **binary** (0% or 100% of its own zone width, not proportional to the
  other):
  - Full-week zone: 100% filled (white) when `filledDays >= 7`, else 0%.
  - Streak zone: 100% filled (white) when `streaksAtThreshold >= 1` (i.e. any streak-bonus tier
    reached — `streaksAtThreshold >= 2` per `consistencyBoost()`'s actual threshold), else 0%.
- **Completion feedback:** when a zone transitions from 0%→100% (i.e. becomes newly earned since
  last view), apply a subtle glow-pulse (D-06 — exact timing/intensity is implementer's discretion,
  base the fill transition on the sketch's `width .8s cubic-bezier(.2,.9,.3,1.1)` easing, wrap the
  pulse keyframe in the established reduced-motion double-guard: `@media (prefers-reduced-motion: no-preference)`
  keyframe + a post-mount JS check skipping the animation class, mirroring
  `CoinAnimation.tsx`/`BottomSheet.tsx`'s existing pattern).
- **Status chips (D-06, required):** two pill chips below the track, `sm` (8px) gap between them:
  - `kidBoost.detail.fullWeekDone` / `fullWeekPending` (with `{{filled}}` interpolation) — mint
    when done, neutral `K.line`/`K.lineSoft` when not.
  - `kidBoost.detail.streakDone` (with `{{count}}` = `streaksAtThreshold`) / `streakPending` —
    mango when done, neutral when not.
  - These chips exist specifically so neither condition "reads as swallowed into a single
    percentage" (D-06's explicit rationale) — do not omit them even though the track already shows
    two zones.

### Empty/zero-week state (D-08)

No separate component/branch. At week start (0 grades, 0 filled days): grades sub-bar renders at
0% fractional fill with its normal `"ещё N пятёрок → +X"` hint (same code path as any other
in-progress week); consistency sub-bar renders both zones at 0% with both chips in `pending` state.
A subtle shimmer/pulse on the empty track (implementer's discretion, using existing CSS
keyframe idioms already in `app/globals.css`) is allowed as a tasteful touch but must not require a
new state variable or new copy — see D-08.

### Data → visual mapping (for the executor)

| Visual element | Source (`lib/kid/boost-rules.ts` / `lib/kid/boost.ts`) |
|---|---|
| Grades sub-bar fill % | `WeeklyGradeStats.topGradeCount` vs. next unreached `BoostSettings.boost_grades_t1_count`/`t2_count` |
| Grades sub-bar penalty state | `WeeklyGradeStats.hasPenaltyGrade` |
| Grades sub-bar hint text | `gradesBoost()`'s `next` string (already computed in `computeWeeklyBoost` → exposed as `WeeklyBoostResult.nextLabel` when grades is the limiting factor) |
| Full-week chip state | `WeeklyConsistencyStats.filledDays >= 7` |
| Streak chip state | `WeeklyConsistencyStats.streaksAtThreshold >= 2` (matches `consistencyBoost()`'s actual `boost_streaks_2` threshold) |
| Total row amount | `WeeklyBoostResult.total` (== `boost.week.total`, identical to the inline `BoostMeter`'s value) |

**Binding note (not itself a visual requirement, but required for the above to render at all):**
`getBoostProgress()` (`lib/kid/boost.ts`) currently returns only the computed `WeeklyBoostResult`
(final coin totals), not the raw `WeeklyGradeStats`/`WeeklyConsistencyStats`/`BoostSettings` inputs
this detail view needs for fractional fills and chip states. The planner/executor must extend what
`getBoostProgress` returns (or add a sibling read) so this UI-SPEC's fill logic has real data to
bind to — flagged in `09.5-CONTEXT.md`'s `<canonical_refs>` as a known integration point, not a new
decision introduced here.

## `boost_style` control (ProfileSheet picker extension, D-09, D-10)

- **Location:** `components/kid/ProfileSheet.tsx`, directly below the existing `fill_style`
  radiogroup (~after line 209) — same self-serve section, no new outer heading (see Copywriting
  Contract note above).
- **Write path:** new `app/kid/actions/boost-style.ts` (`updateChildBoostStyle`), a line-for-line
  mirror of `app/kid/actions/fill-style.ts`'s structure: whitelist array
  `const BOOST_STYLES = ['segmented-bar', 'quest-checklist', 'ring-badges'] as const` validated
  *before* any auth/DB work, `requireFamilyMember()` + `authorizeChildAction()` +
  `createAdminClient().from('children').update({ boost_style: style })` — never a direct client
  write.
- **This phase's picker shows only `segmented-bar` as a selectable option (D-10)** — no
  "coming soon" placeholder UI for `quest-checklist`/`ring-badges`; those appear once Phase 9.6
  ships (mirrors Phase 9.3's D-01 precedent for `fill_style`'s initial single-option state). Render
  as a single full-width option button (not a 3-segment row with 2 disabled slots), using the exact
  same button visual treatment as an *active* `fill_style` option (`background: K.skySoft`,
  `border: 1.5px solid K.sky`, ✓ checkmark) — since it is always both the only choice and the
  active choice this phase.
- **Schema default:** `children.boost_style TEXT NOT NULL DEFAULT 'segmented-bar'` + CHECK
  constraint, mirroring `fill_style`'s migration shape exactly (additive
  `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` + idempotent `DO $$ ... CHECK (...) $$` block).
- Minimum touch target 44px (existing Phase 4.2 convention, already satisfied by the reused button
  treatment).

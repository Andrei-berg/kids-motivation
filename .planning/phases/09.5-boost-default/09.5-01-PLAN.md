<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| kid browser → `'use server'` action | Untrusted `childId` + `style` arguments cross here from a client component |
| server action → Postgres (`children`) | Service-role client bypasses RLS entirely — the guard chain is the only authorization |
| developer machine → prod Postgres | Task 2 runs DDL against the live database with `SUPABASE_DB_URL` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-095-01 | Tampering | `style` argument of `updateChildBoostStyle` | mitigate | `typeof style !== 'string'` + `BOOST_STYLES` allow-list check as the FIRST statement, before `requireFamilyMember()`/`createAdminClient()`; backed independently by the DB `children_boost_style_check` CHECK constraint. Locked in by `tests/boost-style-validation.test.ts`. |
| T-095-02 | Elevation of Privilege | `updateChildBoostStyle` | mitigate | `authorizeChildAction(admin, member, childId)` after `requireFamilyMember()` — a `role === 'child'` member whose `member.childId !== childId` gets `AuthError('Forbidden', 403)`; `assertChildInFamily` then blocks cross-family targets. Byte-identical guard order to `app/kid/actions/fill-style.ts`. |
| T-095-03 | Tampering | `children.boost_style` write path | mitigate | No client-side `.update()` on `children` is introduced anywhere; the migration adds no client UPDATE policy, so `rls.sql`'s family-isolation policies deny any direct browser write to this column. |
| T-095-04 | Denial of Service | prod DDL in task 2 | accept | Migration is additive and idempotent (`ADD COLUMN IF NOT EXISTS`, `DO $$`-guarded constraint) with a `NOT NULL DEFAULT`; no destructive statement, no user-data rewrite. Verified by `scripts/verify-boost-style-column.mjs` before the plan closes. |
| T-095-05 | Information Disclosure | `api.getChild` selecting `*` | accept | `boost_style` is a non-sensitive UI preference; `children` reads are already family-isolated by `rls.sql`, and this adds no column to any cross-family read path. |
| T-095-SC | Tampering | npm/pip/cargo installs | accept | This phase adds no new project dependency. Task 2's `npm i pg --no-save` installs the pre-existing, already-in-use Postgres driver named in CLAUDE.md, non-persistently (`--no-save`, never written to `package.json`) — no supply-chain surface change, so the Package Legitimacy Gate has nothing to audit. |
</threat_model>

**1. Three frozen phrase arrays (D-04, exact strings).** The `« »` guillemets in CONTEXT.md are
delimiters, not part of the copy — store the bare text, emoji included, no surrounding quotes.

`TEASE_ACHIEVEMENT` (6): `Красавчик 🔥`, `Погнали на рекорд!`, `Ну ты и мастер! 😎`,
`Вот это да, снимаю шляпу 🎩`, `Теперь моя очередь удивлять 😏`, `Держись, я догоняю! 💪`

`TEASE_ROUTINE` (6): `Ну погоди 😤`, `Не забудь про уроки 😤`, `Я быстрее наберу 😏`,
`Ты так не сможешь завтра 😏`, `Завтра я тебя обгоню 🏃`, `Скромно, но пойдёт 😏`

`TEASE_PURCHASE` (5): `Всё промотал? 😂`, `Приятной покупки, транжира 💸`,
`А мне не завидно… ну ладно, немного 😏`, `Копи-копи, а потом раз — и нету 😂`,
`Богач нашёлся 👑`

Use the U+2026 ellipsis character in the fourth purchase phrase (`завидно…`), not three dots.
Declare each array `as const` and type the exported value `readonly string[]`.

**2. `TEASE_PHRASES_BY_KIND: Partial<Record<FeedEventKind, readonly string[]>>`** — the same
shape as `RAIL_COLOR_MAP`. Keys: `badge`, `medal`, `streak`, `boost`, `level_up` → the
achievement array; `day_filled`, `reading_approved` → the routine array; `purchase`,
`reward_approved` → the purchase array. Deliberately leave `coins_earned`, `coins_spent` and
`note` out of the map — they are covered by the fallback below, matching how `rankIndex`
handles unranked kinds instead of enumerating them.

**3. `export function teasePhrasesFor(kind: FeedEventKind): readonly string[]`** — returns
`TEASE_PHRASES_BY_KIND[kind] ?? TEASE_ROUTINE`. The Routine fallback is locked (CONTEXT.md
Claude's Discretion); the function must never be able to return an empty array, so do not
return `?? []` and do not gate on `kind in TEASE_PHRASES_BY_KIND`.

**4. `export const ALL_TEASE_PHRASES: readonly string[]`** — the flattened union of the three
arrays (17 entries, no duplicates across groups).

**5. `export function isKnownTeasePhrase(text: string): boolean`** — exact membership test
against `ALL_TEASE_PHRASES` (use a module-level `Set` built once; compare the raw string, no
trimming, no case folding). This is the anti-forgery hook plan 09.2-04's render path relies on.

**6. A header comment** stating: this module is the single source of the tease copy; it is
imported by both `lib/repositories/feed.repo.ts` and `components/feed/FamilyFeed.tsx`; if a
phrase is ever removed from a group, it must be moved into a `LEGACY_TEASE_PHRASES` array that
`ALL_TEASE_PHRASES` still includes, otherwise already-stored teases would stop rendering as
teases.

Then create `tests/tease-phrases.test.ts` with a `describe('FEED-06 tease phrases')` block
asserting: each group's exact length (6/6/5); `ALL_TEASE_PHRASES.length === 17` and
`new Set(ALL_TEASE_PHRASES).size === 17`; every one of the 12 `FeedEventKind` values passed
through `teasePhrasesFor` yields a non-empty array (iterate a literal array of all 12 kinds);
`teasePhrasesFor('note')`, `teasePhrasesFor('coins_earned')` and `teasePhrasesFor('coins_spent')`
each `toBe(TEASE_ROUTINE)` (identity, proving the fallback rather than an accidental copy);
`teasePhrasesFor('badge')` equals `TEASE_ACHIEVEMENT`; `isKnownTeasePhrase('Ну погоди 😤')` is
true and `isKnownTeasePhrase('Ну погоди')` is false.

Append tease helpers to `lib/repositories/feed.repo.ts` and make the two existing comment
readers tease-blind. `family_event_comments` has no `metadata` column, so the tag is a
reserved body prefix (D-06, implementer's call) — no migration, no new RLS policy, no new
realtime subscription.

**1. `export const TEASE_PREFIX = '[[tease]] '`** — ASCII marker plus one trailing space.
Declare it next to the comment functions with a comment explaining it is a storage convention
stripped at render time, never shown to a user.

**2. `export function isTeaseComment(c: FeedComment): boolean`** — true only when
`c.body.startsWith(TEASE_PREFIX)` **and** `isKnownTeasePhrase(c.body.slice(TEASE_PREFIX.length))`.
Both conditions are required: the phrase-set check is what stops a kid from hand-typing
`[[tease]] anything` into the ordinary comment box and having it render as a grape tease bubble.
Import `isKnownTeasePhrase` from `@/lib/kid/tease-phrases`.

**3. `export function teaseTextOf(c: FeedComment): string`** — `c.body.slice(TEASE_PREFIX.length)`
when `isTeaseComment(c)`, otherwise `c.body` unchanged.

**4. `export async function addTeaseReply(params: { eventId: string; familyId: string; authorMemberId: string; authorName: string; phrase: string }): Promise<FeedComment | null>`**
— returns `null` immediately when `!isKnownTeasePhrase(params.phrase)` (never write unvalidated
text through this path), otherwise delegates to the existing `addComment` with
`body: TEASE_PREFIX + params.phrase` and returns its result. Do not duplicate the insert; call
`addComment` so the RLS-bound browser client and the error logging stay a single code path.

**5. `export async function getTeaseRepliesByFamily(familyId: string): Promise<Record<string, FeedComment[]>>`**
— mirrors `getReactionsByFamily`'s shape: select `*` from `family_event_comments`
`.eq('family_id', familyId)`, `.like('body', `${TEASE_PREFIX}%`)`,
`.order('created_at', { ascending: true })`; on error log `[feed.repo] getTeaseRepliesByFamily error:`
and return `{}`; group surviving rows by `event_id`, skipping any row where `isTeaseComment` is
false (prefix present but phrase not in the locked set).

**6. `export function hasTeased(rows: FeedComment[] | undefined, myMemberId: string | null): boolean`**
— pure, no I/O (same discipline as `summarizeReactions`): true when `myMemberId` is non-null and
some row has `author_member_id === myMemberId`. This is the D-07 one-tease-per-(person, card)
check; it runs off the already-loaded map, so it costs no extra query.

**7. Make the plain comment stream tease-blind.** In `getComments`, return
`(data ?? []).filter(c => !isTeaseComment(c as FeedComment))` — teases render as their own
bubbles under the card, not as rows in the thread. In `getCommentCounts`, change the select
from `'event_id'` to `'event_id, body'`, type the rows as `{ event_id: string; body: string }`,
and skip rows that satisfy `isTeaseComment` (construct the minimal object or reuse the
prefix+phrase test directly) so a tease never increments the 💬 badge. Leave both functions'
error handling, ordering, and return types exactly as they are.

Do not touch `addComment`, `addReaction`, `removeReaction`, `getFeed`, `getFeedUnreadCount`,
`subscribeFeed`, or the localStorage helpers.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (kid/parent session) → `family_event_comments` via the RLS-bound anon client | The only write this plan adds. RLS is the enforcement layer: INSERT requires `family_id` ∈ the caller's families AND `author_member_id` = the caller's own `family_members.id`. |
| `family_event_comments` rows → feed render | Stored text (attacker-influenceable within the family) crosses into the tease-bubble render path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-092-01 | Spoofing | `addTeaseReply` → `family_event_comments` INSERT | mitigate | No service-role path is introduced; the write reuses `addComment` on the RLS-bound browser client, so the existing `"Family members add event comments"` policy pins `family_id` and `author_member_id` to the authenticated member. A client-supplied `familyId`/`authorMemberId` that does not match the session is rejected by Postgres, not by app code. |
| T-092-02 | Tampering | Tease tag convention (`[[tease]]` body prefix) | mitigate | `isTeaseComment` requires the prefix **and** exact membership in the 17-phrase locked set, so a hand-typed `[[tease]] gotcha` in the ordinary comment box renders as a plain comment. The worst residual case is re-posting one of the app's own approved phrases — identical in effect to using the tray. |
| T-092-03 | Tampering | `addTeaseReply` body content | mitigate | The function returns `null` for any phrase outside `ALL_TEASE_PHRASES`, so this path cannot become a freeform-text channel (UI-SPEC content rule 2). |
| T-092-04 | Information disclosure | `getTeaseRepliesByFamily` | mitigate | Query is `.eq('family_id', familyId)` on top of the family-scoped SELECT RLS policy; a mis-supplied `familyId` returns zero rows rather than another family's data. |
| T-092-05 | Denial of service | Unbounded tease rows per card | accept | D-07 caps a person to one tease per card in the UI (plan 09.2-04) and the tray offers at most 6 buttons; a scripted family member could still insert extra comment rows, which is the pre-existing comment-spam surface, unchanged by this plan. |
| T-092-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs **zero** packages (`git diff package.json` must be empty). No `[ASSUMED]`/`[SUS]` package review is triggered. |
</threat_model>

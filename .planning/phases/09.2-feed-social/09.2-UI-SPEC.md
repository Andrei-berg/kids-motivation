# Phase 9.2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — shadcn deliberately not used (unchanged from Phase 9.1) |
| Preset | not applicable |
| Component library | none (hand-rolled React function components, inline `style` objects) |
| Icon library | none — emoji glyphs only, consistent with the entire kid design system |
| Font | Rubik (`K.fDisp`, headings/numbers) + Nunito (`K.fBody`, body) on kid variant; daylight `family/parent` variant keeps `familyBase.fontDisplay`/`fontBody` (Bitter/Golos), unchanged by this phase |

**Why no shadcn:** Identical rationale to Phase 9.1 (`.planning/phases/09.1-feed-recognition/09.1-UI-SPEC.md`) — `components.json` is absent, and this phase extends the same hand-rolled `FamilyFeed.tsx`/`kidTheme.ts`/`atoms.tsx` system Phase 9.1 restyled, not a new surface. All three new UI pieces (expanded reaction picker, tease tray/reply bubble, kid-medal composer) are additive changes inside that existing component, in both the kid-theme and daylight-theme variants `FamilyFeed` already renders for.

## Spacing Scale

Declared values (must be multiples of 4), inherited unchanged from Phase 9.1 — this phase does not introduce a new spacing token, only new usages of the existing ones:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside chips/tray buttons |
| sm | 8px | Reaction-row gaps, tease-tray gap between phrase buttons, chip internal spacing |
| md | 16px | Default spacing between cards, tray padding-top-border offset |
| lg | 24px | Section breaks (unchanged from 9.1, not touched by this phase) |
| xl | 32px | Modal top/bottom safe-area padding (kid-medal composer sheet) |

Exceptions (carried over unchanged, do not "fix" to fit 8pt, do not introduce new off-scale values):
- `18px` card border-radius — established shape token, used again for the medal-composer sheet's top corners
- `14px` card body padding — established (`EventRow`/`.synth-body`)
- `1px dashed` border-top on the tease tray (`padding-top: 8px`) — locked value from the validated sketch CSS (`.tease-tray`), reused verbatim
- `6px 12px` tease-button / `6px 11px` tray-phrase-button padding — locked sketch values, not 8pt-scale but pre-validated pill-button proportions consistent with existing `reaction-chip` (`5px 10px`) sizing; do not round these

## Typography

Inherited unchanged from Phase 9.1 (exactly 2 weights: 400 regular / Nunito body, 700 bold / Rubik headings-labels-numbers). This phase adds no new typography role — every new text element (reaction chip, tease button, tray phrase button, tease-reply bubble, medal-composer phrase button, medal feed-card sender line) maps onto an existing declared role:

| Role | Size | Weight | Line Height | New usages this phase |
|------|------|--------|-------------|------------------------|
| Label (meta/timestamp/count/button text) | 12px | 700 | 1.3 | Tease button label ("Подколоть"), tray phrase buttons, reaction chip emoji+count (12px per existing `EventRow` reaction-chip render, unchanged) |
| Body (card sub-line, comment text) | 14px | 400 | 1.5 | Not used for new elements — all new buttons/labels use the 700-weight Label role, matching the sketch's `.tease-btn`/`.tease-tray button` font-weight 700 |
| Heading (card headline) | 16px | 700 | 1.35 | Unchanged — medal card headline text still flows through the existing `EventRow` title render |

Tease-reply bubble text: 13px / 700 / line-height 1.4 — matches the sketch's `.tease-reply` (`font-size: 13px; font-weight: 700`), one step below Label size but same weight; declare as a Label-role variant, not a new role. No new font weight is introduced (still exactly 400 + 700; the 800 exception from 9.1 is unused by this phase).

| Role | Value | Usage |

### New/expanded accent usages (D-01, D-04–D-07, D-11, D-12 — locked)

| Element | Color | Token | Rationale |
|---|---|---|---|
| Reaction chip "lit" state (all 6 emoji, not just the current 4) | mango | `K.mango` border / `K.mangoSoft` background / `K.mangoDeep` text | Unchanged from existing `reaction-chip.lit` treatment in `EventRow` — extending to 6 emoji does not change the color, only the emoji set (`QUICK_EMOJI` → all of `FEED_REACTION_EMOJI`: ❤️ 👍 🔥 🏆 😂 🎉) |
| Tease button (`.tease-btn`) | neutral | `K.lineSoft` background, `K.ink3` text (unlit/idle) | Matches sketch `.tease-btn` (`background: var(--color-border-soft); color: var(--color-text-muted)`) — deliberately muted/neutral, not competing with the reaction row's mango accent |
| Tease tray phrase buttons | grape | `K.grape` border, `K.grapeSoft` background, `K.grapeDeep` text | Locked from sketch `.tease-tray button` (`border: var(--grape); background: var(--grape-soft); color: var(--grape-deep)`) — grape is reserved elsewhere for level/XP/achievement, but the sketch validated grape specifically for the tease-tray's playful-rivalry tone; do not substitute mango or berry here |
| Tease-reply bubble | grape | `K.grapeSoft` background, `K.grapeDeep` text | Matches sketch `.tease-reply` — same grape family as the tray button that produced it, visually linking trigger → result |
| Medal rail (parent-sent AND kid-sent, both) | berry | `K.berry` `#FF6B8A` | Unchanged from 9.1's Rail Color Map (D-08 in 9.1) — `kind: 'medal'` always renders berry regardless of sender; this phase does not add a second rail color to distinguish kid-sent from parent-sent (distinction is copy-only, per D-12, not color-only) |
| Medal-composer phrase picker buttons (new, kid-initiated send flow) | berry | `K.berry` border, `K.berrySoft` background, `K.berryDeep` text | New element, not in the sketch (the sketch only shows the tease tray, not a medal-send picker) — berry chosen for consistency with the medal rail/theme it produces, mirroring how the tease tray borrows grape from its own semantic family |

This phase does not touch the Rail Color Map table itself (still 9.1's locked mapping) and does not add new `family_events.kind` values — kid-sent and parent-sent medals both emit `kind: 'medal'`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — tease button | "Подколоть" (locked, matches sketch exactly) |
| Primary CTA — medal send (new kid-initiated entry point) | "Отправить медаль" as the button that opens the phrase picker; no freeform confirm step needed beyond the picker itself (picking a phrase = sending, matching the tray's one-tap-sends pattern from D-06/tease) |
| Tray/tray-adjacent state — tease already sent (D-07, re-tap) | Recommended default (Claude's discretion per CONTEXT.md): tray does not reopen; tease button shows a confirmed/disabled visual state with label "Подколото" (past tense) instead of a toast — consistent with reactions' silent, count-only feedback style (D-03) rather than introducing a new toast pattern the sketch's `.toast` class exists for but is not required by any locked decision here |
| Empty state — tease tray content for uncategorized kinds (`coins_earned`, `coins_spent`, `note`) | Not a distinct message — falls back silently to the Routine group's 6 phrases (per Claude's Discretion in CONTEXT.md); the tray must never render with zero buttons |
| Medal feed card — kid-sent sender line (D-12) | "Медаль от {sibling display name} 🏅" |
| Medal feed card — parent-sent sender line (unchanged) | "Медаль дня 🏅" |
| Medal-composer phrase picker heading (new sheet) | "Отправить медаль {sibling name}" |
| Medal-composer daily-cap-reached state | "Ты уже отправил медаль сегодня" — shown in place of the phrase list when the sender has hit the D-10 one-medal-per-day-total cap; no separate error toast needed, this replaces the picker content |
| Error state | Not a requirement of this phase; if the new kid-medal server action call fails (network/validation), reuse the existing inline-message pattern already used elsewhere in kid UI (e.g. `sendMedal`'s existing `{ success: false, error }` shape) rendered as small red (`K.danger`) text below the picker — optional polish, not blocking |
| Destructive confirmation | Not applicable — no destructive action in this phase's scope |

### Content rules (hard constraints — carried forward from 9.1, still binding)

1. **No coin/money amount ever renders**, including on a kid-sent medal card (which is coins=0 per D-08) — the existing `amount` span removal from 9.1 already covers this; do not reintroduce an amount render for medal cards specifically.
2. **No freeform text anywhere in this phase's new UI** — tease phrases (D-04, 17 fixed phrases) and medal phrases (D-11, 8 fixed phrases) are both locked, pre-written sets; do not add a text input as an alternative or "custom message" escape hatch to either the tease tray or the kid-medal composer.
3. Tease and medal phrase button copy must render **exactly** the locked strings from CONTEXT.md D-04/D-11 (including emoji) — do not paraphrase, retranslate, or drop the trailing emoji.

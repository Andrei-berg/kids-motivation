Create `components/feed/MedalComposer.tsx` — `'use client'`, default-exported function
component. Kid-only surface, so it sources colour and type from `K` directly (no `palette()`
variant object, no daylight tokens).

**Props:** `{ siblings: Child[]; onClose: () => void }`. The caller passes only siblings
(already excluding the sender's own child) — the composer does no filtering, no family lookup
and no Supabase query of its own.

**Local state:** `target: Child | null` (initialised to `siblings[0]` when `siblings.length === 1`,
otherwise `null`), `sending: boolean`, `capped: boolean`, `error: string | null`.

**Shell:** copy `ProfileSheet`'s structure — `role="dialog"`, `aria-modal="true"`, fixed-inset
backdrop `rgba(33,49,74,0.5)` at `zIndex: 240` with `onClick={onClose}`, inner panel with
`onClick={e => e.stopPropagation()}`, `width: '100%'`, `maxWidth: 480`, `background: K.cream`,
`padding: '18px 18px 32px'`, `maxHeight: '90vh'`, `overflowY: 'auto'`,
`animation: 'slideUp 0.28s cubic-bezier(.2,.9,.3,1.1)'`, and the 40×4 `K.line` handle bar. Use
`borderTopLeftRadius: 18` / `borderTopRightRadius: 18` — 18, not ProfileSheet's 26, because
UI-SPEC pins the established card-radius token for this sheet. Close on `Escape` via a
`useEffect` keydown listener that is removed on unmount (the `StoryMomentModal` pattern in
`FamilyFeed.tsx`).

**Step 1 — sibling picker**, rendered only when `target === null`: heading
`Кому отправить медаль?` (`K.fDisp`, 16, 700, `K.ink`), then one full-width button per sibling:
`display: 'flex'`, `alignItems: 'center'`, `gap: 10`, `padding: '10px 12px'`,
`borderRadius: 14`, `border: '1.5px solid ' + K.line`, `background: K.card`, `cursor: 'pointer'`,
containing a 34px round glyph circle (`child.emoji || '🙂'`, `background: K.berrySoft`) and the
child's name (`K.fDisp`, 14, 700, `K.ink`). `onClick` sets `target`.

**Step 2 — phrase list**, rendered when `target !== null` and `!capped`: heading
`Отправить медаль {target.name}` (exact copy from UI-SPEC), then `MEDAL_PHRASES.map(...)` as
full-width stacked buttons: `key={phrase}`, `textAlign: 'left'`, `padding: '10px 14px'`,
`borderRadius: 999`, `border: '1.5px solid ' + K.berry`, `background: K.berrySoft`,
`color: K.berryDeep`, `fontFamily: K.fBody`, `fontSize: 12`, `fontWeight: 700`,
`cursor: sending ? 'default' : 'pointer'`, `disabled={sending}`, `opacity: sending ? 0.6 : 1`,
stacked in a `display: 'flex', flexDirection: 'column', gap: 8` column. The label is the phrase
verbatim, emoji included (UI-SPEC Content rule 3). Picking a phrase **is** sending — there is no
confirm step. When `siblings.length > 1`, also render a small text button `← Другой получатель`
that clears `target`, so a wrong pick is recoverable without closing the sheet.

**Send handler:** guard on `sending`/`!target`; set `sending`, clear `error`; call
`await sendKidMedal({ targetChildId: target.id, phrase })`. On `success` → `onClose()` (the new
card arrives through the feed's existing realtime subscription; do not refetch and do not render
a coin figure or a success toast). On failure → if
`res.error === 'Ты уже отправил медаль сегодня'` set `capped = true`, otherwise set
`error = res.error ?? 'Не получилось отправить'`. Always clear `sending` in a `finally`.

**Capped state:** when `capped`, replace the phrase list (and the picker) with the single line
`Ты уже отправил медаль сегодня` (`K.fBody`, 14, 400, `K.ink2`) plus a `Закрыть` button — no
toast, no phrase buttons, matching UI-SPEC's Copywriting Contract.

**Error line:** when `error`, render it below the list as 12px `K.danger` text; it never
replaces the phrase list (only the cap does).

**Hard constraints:** no `<input>`, `<textarea>` or `contentEditable` anywhere in this file
(Content rule 2 — the kid medal has no custom-message escape hatch); no coin amount, `🪙`
glyph, or "+N монет" copy anywhere (D-08 and 9.1 D-01); no direct Supabase import — the only
data path is the `sendKidMedal` server action.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Composer (browser) → `sendKidMedal` server action | The only privileged path; the client supplies `targetChildId` + `phrase` and nothing else. |
| Client-side visibility rules (`canSendMedal`, sibling filter) | Convenience only — never a security control. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-092-30 | Elevation of privilege | Hiding the launcher as authorization | mitigate | The UI guard (`variant === 'kid' && role === 'child'`) is cosmetic; the server action independently enforces child-role, non-self target and same-family target (T-092-07/08/09, proven by plan 09.2-04). A parent or a tampered client calling the action directly still gets 403. |
| T-092-31 | Tampering | Sibling list filtered client-side | mitigate | `siblings` is derived from the RLS-scoped `getChildren()` result, and `assertChildInFamily` re-derives the family server-side; a hand-crafted `targetChildId` from another family is rejected regardless of what the picker rendered. |
| T-092-32 | Tampering | Freeform medal text via the UI | mitigate | No text entry exists in the composer (grep gate) and the server re-validates against `MEDAL_PHRASES`, so the flow cannot become a free-text channel even with a modified client. |
| T-092-33 | Information disclosure | Coin figures leaking onto a kid surface | mitigate | The composer contains no `🪙`/"монет" copy (grep gate) and the medal is coins-0; the feed card emits `amount: null`, preserving 9.1 D-01. |
| T-092-34 | Denial of service | Rapid repeated taps on a phrase button | mitigate | `sending` disables the buttons during the round trip, and the server's two caps plus the unique indexes make a duplicate impossible even if the guard is bypassed. |
| T-092-35 | Spoofing | Sender name shown on the resulting card | mitigate | The card title is composed server-side from `family_members.display_name` of the authenticated sender; the composer never sends a name. |
| T-092-SC | Tampering | npm/pip/cargo installs | mitigate | No package added; the sheet reuses `ProfileSheet`'s inline-style pattern and the existing `slideUp` keyframe. |
</threat_model>

## v1 Requirements — Final Status

### Family Feed (FEED)

- [x] **FEED-01**: Kid and parent can see a story-reel of each child's single biggest highlight
  for today at the top of the Feed screen; tapping it opens a full celebratory moment view.
- [x] **FEED-02**: Feed shows a day-grouped list of event cards (day completed, streak, boost,
  badge, medal, reading approved, reward purchased, parent free-text note) with a color-coded
  left status rail indicating event type — reusing the existing `CollapsibleRow` rail pattern.
- [x] **FEED-03**: Feed never displays money amounts or coin costs for reward purchases — only
  the reward name (e.g. "Адам взял час приставки", never a price/coin figure).
- [x] **FEED-04**: Feed never displays penalties, corrections, or negative behavior-tag events —
  those remain visible only in the private Wallet/audit trail.
- [x] **FEED-05**: Any family member can react to a feed event with a fixed emoji set
  (toggleable per user, with visible count).
- [x] **FEED-06**: A child can send a sibling a "подколоть" (tease) reply chosen from a fixed set
  of pre-written playful phrases (not freeform text); it posts inline under the event card.
- [x] **FEED-07**: A medal sent kid→kid posts to the feed as its own recognized event type.

### Day-fill Form Styles (DAYFORM)

- [x] **DAYFORM-01**: Each child has a `fill_style` preference (`tile-sheet` / `story-stepper` /
  `sticky-summary`) that is settable and changeable anytime from the child's profile/settings.
- [x] **DAYFORM-02**: `tile-sheet` style — the whole day renders as a grid of per-category status
  tiles; tapping a tile opens a bottom sheet scoped to that category only.
- [x] **DAYFORM-03**: `story-stepper` style — one category fills the screen at a time with a
  dot-progress track; completing a category auto-advances to the next incomplete one, with an
  explicit skip control.
- [x] **DAYFORM-04**: `sticky-summary` style — a persistent completion ring + live coin total
  stays on screen; binary categories are answered with one tap directly on their row (no
  sheet/accordion); multi-value categories expand a small inline panel in place.
- [x] **DAYFORM-05**: All three fill styles show live coin-earning feedback (a floating amount
  and a ticking running total) on every category filled.
- [x] **DAYFORM-06**: Default `fill_style` for a child with no explicit preference is
  `sticky-summary` (closest to current behavior).

### Weekly Boost Detail Styles (BOOST)

- [x] **BOOST-01**: Each child has a `boost_style` preference (`segmented-bar` /
  `quest-checklist` / `ring-badges`) that is settable and changeable anytime from the child's
  profile/settings.
- [x] **BOOST-02**: Tapping the existing inline `BoostMeter` on the Day hero opens the chosen
  `boost_style` detail view; the inline meter itself stays visually unchanged.
- [x] **BOOST-03**: `segmented-bar` style shows the grades-tier progress and the
  consistency-bonus progress as two independent sub-bars with their own hint text.
- [x] **BOOST-04**: `quest-checklist` style lists each boost condition (grade-tier thresholds,
  full-week completion, streak-threshold) as its own row with its own reward amount and
  progress, plus one combined total at the bottom.
- [x] **BOOST-05**: `ring-badges` style shows one ring for the current total plus tappable tier
  badges (reached / next) that open a popover explaining what's needed for the next tier.
- [x] **BOOST-06**: All three boost-detail styles read real tier thresholds and coin amounts from
  `lib/kid/boost-rules.ts` — no hardcoded illustrative values from the sketches. Proven for
  `segmented-bar` in Phase 9.5 and held for `quest-checklist`/`ring-badges` in Phase 9.6.

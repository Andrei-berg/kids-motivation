# Milestone v9.0: Kid Experience Redesign

**Status:** ✅ SHIPPED 2026-09-20
**Phases:** 9.1–9.6
**Total Plans:** 32

## Overview

Turned the Family Feed into the family's motivational social network and gave kids a fast,
transparent, personalized way to log their day and understand their weekly boost — replacing
the previous flat activity log, single-open-accordion fill form, and one-line boost hint.
Grounded entirely in `.claude/skills/sketch-findings-kids-motivation/` (validated design
decisions, CSS patterns, and interactive HTML mockups from the 2026-09-17 sketch session).
Numbered v9.0 (not v6.0) and phases start at 9.1 specifically to avoid colliding with the
already-reserved-but-unbuilt v6.0/v7.0/v8.0 phase numbers (6.1–8.3).

## Phase Details

### Phase 9.1: feed-recognition
**Goal**: Kid and parent see the Family Feed reframed as a motivational recognition stream — today's highlights up top, day-grouped event cards below — with no money or penalty content ever shown
**Depends on**: Nothing (first v9.0 phase)
**Requirements**: FEED-01, FEED-02, FEED-03, FEED-04
**Success Criteria** (what must be TRUE):
  1. Opening the Feed shows a story-reel bubble per child with today's single biggest highlight; tapping a bubble opens a full celebratory moment view
  2. Below the story reel, events are grouped by day into cards, each with a color-coded left rail matching its event type (day completed, streak, boost, badge, medal, reading, purchase, parent note) reusing the real `CollapsibleRow` rail pattern
  3. A reward purchase card in the feed shows only the reward's name, never a coin amount or price
  4. No card in the feed ever shows a penalty, correction, or negative behavior-tag event — those stay visible only in the private Wallet/audit trail

## Milestone Summary

**Key Decisions:**
- Feed content rules held hard across both feed phases: no money amounts/coin costs, no
  penalties/corrections/negative behavior-tag events — enforced by regression-guarded vitest
  suites, not just review.
- `fill_style` and `boost_style` both modeled as per-child columns on `children` (not a separate
  settings table), mirroring the existing `backfill_mode` pattern.
- Tease (`подколоть`) and kid→kid medals both ship with zero freeform text — locked phrase sets
  only, by explicit design decision.
- `BOOST-06`'s "no hardcoded sketch numbers" rule was treated as a standing regression
  requirement re-verified in both Phase 9.5 (segmented-bar) and Phase 9.6 (quest-checklist,
  ring-badges), not a one-time check.
- Phase-close discipline (established in 09.3-06, reused verbatim through 09.6-05): automated
  gate sweep + live-schema re-check + full decision traceability matrix + operator browser
  sign-off, rather than trusting a ROADMAP "Complete" marker — direct mitigation of the Phase 1.3
  "roadmap complete ≠ migration ran" failure mode from v5.0.

**Issues Resolved:**
- Phase 9.1: apparent "no story bubbles" report was a local-midnight day-rollover artifact, not a
  bug — diagnosed via a direct `family_events` query rather than guessing from the UI.
- Phase 9.2: 1 pre-existing RLS gap on `family_event_reactions` INSERT policy (introduced in
  Phase 9.1, caught here) plus 5 minor robustness warnings — all closed, logged in
  09.2-VERIFICATION.md.
- Phase 9.3: 1 pre-existing blocker (`KidDayFillForm.isLocked` ignoring `children.backfill_mode`,
  traced via git blame to Phase 5.6, not introduced in 9.3) plus 3 minor warnings — none blocking.
- Two `check.decision-coverage-plan` false positives (Phase 9.1 and Phase 9.2 planning) from a
  known parser bug on CONTEXT.md's multi-line/nested decision bullets — both manually verified
  as full coverage via grep + independent `gsd-plan-checker` pass before proceeding.
- Milestone-close audit: `.planning/REQUIREMENTS.md` had stale unchecked boxes for FEED-01..04
  despite Phase 9.1 being operator-verified complete on 2026-09-18 — corrected in the archived
  requirements file; ROADMAP.md's progress table for 9.5/9.6 was similarly stale ("In
  Progress"/"Not started" despite both phases' plan lists showing all plans checked) — corrected
  on archive.

**Issues Deferred:**
- Phase 9.6: `QuestChecklistBody`'s total progress bar can hit `NaN%` if a family zeroes out all
  boost coin settings (an existing edge case, `RingBadgesBody`'s identical calculation is
  correctly guarded) — non-blocking Warning, not fixed in this milestone.
- No milestone-level `/gsd:audit-milestone` was run before this close (operator chose to proceed
  without it, given every phase already carried its own gate-sweep + traceability + operator
  sign-off close).

**Technical Debt Incurred:**
- None new. The `QuestChecklistBody` NaN% edge case above is the only known open item from this
  milestone's code.
